Новая гонка **Дуатлон 222** (05.09.2026, один массовый старт, 3 этапа: бег 10 км → вело 170 км → бег 42 км, зачёт только абсолютный М/Ж, без возрастных категорий, без эстафет). Проект того же организатора «Triatleta», что и суточная велогонка ([[project_km_track]] — там же прецедент `src/triatleta/`).

**Дизайн и план зафиксированы 2026-08-24** после сессии вопрос-ответ с пользователем:
- Дизайн-док: `docs/superpowers/specs/2026-08-24-duathlon-222-design.md`
- План с чекбоксами: `docs/superpowers/plans/2026-08-24-duathlon-222.md`

**Ключевые решения:**
- Трекер/GPX-карта не нужны — гонка круговая (как суточная велогонка), точки на маршруте бессмысленны.
- Хостинг: тот же домен `live-race.triatleta.ru`, путь `/duathlon222` (не отдельный поддомен) — переиспользует уже выпущенный SSL.
- Формат старта: один общий массовый старт, дальше личное непрерывное время (T1/T2 без гандикапа) — как в классическом дуатлоне.
- На странице результатов нужны явные колонки по этапам (Бег-1/Вело/Бег-2), не только общее время.

**Архитектурный выбор (важно для будущих сессий):** в проекте два прецедента многосоставных гонок — `src/triatleta/` (tri_24h, N одинаковых кругов, таблица `laps`) и `src/siberman/` (разные дисциплины, широкие колонки по этапам на участника). Дуатлон 222 структурно ближе к Siberman (3 РАЗНЫЕ дисциплины, нужны отдельные колонки по этапам) — поэтому выбрана модель широких колонок (`run1_s`/`bike_s`/`run2_s` в таблице `participants` новой БД `duathlon_222`, время этапа = вычитание соседних кумулятивных отметок), а не модель кругов tri_24h. Данные при этом берутся live-поллингом из Copernico API как у tri_24h (не Excel-парсинг как в Siberman) — гибрид двух прецедентов.

**Блокер (Task 0/1/3 в плане):** структура Copernico и точное время старта (`gun_time`) 05.09.2026 всё ещё не подтверждены организаторами (последняя проверка 2026-09-02, за 3 дня до гонки). Task 0: рабочее предположение — один event с полями трёх этапов (Вариант А), конфиги написаны под него с плейсхолдерными именами полей (`times.official_run1`/`bike`/`finish` — догадка по конвенции, не подтверждено). Task 1 частично готово: БД `duathlon_222` создана и применена на VPS (2026-09-02, `src/duathlon222/migrations/001_init.sql` через `python -m deploy.ssh_apply_duathlon222_migration`), но запись в `events` ещё не вставлена — ждёт `gun_time`. Task 3 (загрузчик `load_duathlon_results.py`) написан, но не запускался вживую — ждёт реальных полей Copernico.

**2026-09-02: реализовано всё, что НЕ зависит от Copernico/gun_time** (Tasks 4-7 плана) — DB-слой (`src/duathlon222/db.py`/`service.py`), полный FastAPI-модуль с админкой (`src/duathlon222/router.py`: логин/сессия, управление systemd-загрузчиком, редактор YAML-пресета в браузере — по образцу `race_triatleta`), HTML-страницы (простая таблица с колонками по этапам, без графиков — сознательно проще боевого `tri_results.html`), правка `deploy/nginx.conf` (домен `live-race.triatleta.ru` держит explicit whitelist путей, не catch-all — правка была обязательна). Всё локально протестировано через `TestClient`, полный набор `tests/unit/` 408/408 без регрессий. **Важная находка по ходу:** реальная кодовая база продукта называется `src/race_triatleta/` (не `src/triatleta/` — переименовано в `docs/superpowers/plans/2026-07-06-project-restructure.md`), заметно богаче изначального MVP-дизайна суточной гонки — при работе с этим продуктом в будущем сверяться с актуальным кодом, не со старыми design-doc'ами.

Ничего из сделанного 2026-09-02 ещё не закоммичено (пользователь коммиты не запрашивал).

**Why:** дедлайн 05.09.2026, гонка новая, нужна отдельная от krasmarafon/tri_24h/siberman инфраструктура, чтобы не рисковать регрессией в уже работающих продуктах (тот же принцип изоляции, что у `load_tri_results.py` не трогающего `load_race_results.py`).
