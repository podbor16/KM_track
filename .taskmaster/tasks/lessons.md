# Уроки

## Импорт обязан сохранять исходные timestamp'ы, не полагаться на DEFAULT (2026-09-10)

**Ошибка:** `bulk_import_leads()` при INSERT новых заявок из файла Tilda не
заполнял `leads.created_at` → срабатывал `DEFAULT CURRENT_TIMESTAMP` → у всех
импортных строк дата регистрации = момент импорта. Незаметно ~полгода, пока
не полезли смотреть чарт динамики регистраций в DataLens: у Жары-2026 все
~3500 заявок «зарегистрированы» в августе (реконсиляция стартового списка),
кривая роста регистраций сломана на 3 чартах сразу (Д1/Д1%/Д2).

**Почему не заметили раньше:** 2024–2025 данные пришли через вебхук в
реальном времени — там `DEFAULT CURRENT_TIMESTAMP` даёт верную дату. Порча
только у пути, где событие произошло в прошлом, а строка создаётся сейчас.

**Правило:**
- Любой импорт/бэкфилл/миграция, создающая строки задним числом, ДОЛЖНА
  переносить исходные временны́е метки из источника. `DEFAULT
  CURRENT_TIMESTAMP` / `NOW()` корректны ТОЛЬКО для realtime-путей (вебхук,
  живой ввод).
- Перед тем как игнорировать колонку источника («в нашей таблице для неё нет
  поля») — проверить, не понадобится ли она аналитике/отчётности. Колонку
  `Date` выгрузки Tilda годами держали в `_KNOWN_IGNORED_HEADERS`.
- При UPDATE существующих строк дату двигать только НАЗАД (`LEAST(col, new)`)
  — не затирать более раннюю реальную метку из другого источника.

**Диагностический приём:** распределение по месяцам (`GROUP BY
DATE_FORMAT(col,'%Y-%m')`) сразу показывает «всё в одном месяце» = дата
проставлена пачкой, а не по событию.
