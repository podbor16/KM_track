# Дуатлон 222 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Запустить live-результаты Дуатлона 222 на `live-race.triatleta.ru/duathlon222` к старту гонки 05.09.2026 (единый массовый старт, 3 этапа: бег 10 / вело 170 / бег 42).

**Design doc:** `docs/superpowers/specs/2026-08-24-duathlon-222-design.md`

**Architecture:** Новый изолированный модуль `src/duathlon222/` в существующем FastAPI-приложении, подключается на том же домене `live-race.triatleta.ru`, что и суточная гонка, но по пути `/duathlon222` (не отдельный поддомен). Отдельная БД `duathlon_222` на том же MySQL VPS. Новый загрузчик `load_duathlon_results.py` опрашивает Copernico. Хранение — широкие колонки по этапам на участника (модель Siberman), не таблица кругов (модель tri_24h) — см. дизайн-док, раздел "Архитектурный выбор". Трекер/карта/GPX не нужны (гонка круговая).

**Tech Stack:** FastAPI, MySQL (mysql-connector-python), Jinja2, systemd, Copernico API

## Task 7: nginx — ГОТОВО (2026-09-02)

**Важная находка:** у `live-race.triatleta.ru` nginx не проксирует всё подряд — явный whitelist `location ~ ^/(24h|api/tri) {...}`, остальное `location / { return 404; }` (изоляция доменов, найдено пользователем 2026-07-24). Правка nginx была обязательна, не опциональна.

- [x] Расширен regex: `^/(24h|api/tri|duathlon222|api/duathlon222)` в `deploy/nginx.conf`
- [x] Добавлен `location = /` — корень отдавал 404 (отсутствовал в whitelist), хотя domain-aware `/`-хендлер и страница выбора гонки (`race_triatleta/index.html`) уже существовали в коде с 2026-07-06 — просто были технически недоступны. Обе карточки (24h + Дуатлон 222) теперь ведут на реальные страницы.
