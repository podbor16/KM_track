# Дизайн: Бар-чарт сегментов в детальной панели

> **Дата:** 2026-05-14  
> **Статус:** Approved

---

## Контекст

Детальная панель участника в `/results` показывала все пары КТ (~28 строк для полумарафона). Это нечитаемо. Новый дизайн: бар-чарт темпа по последовательным отрезкам + две компактные таблицы (отрезки и сплиты).

---

## Что меняется

**Заменяется:** функция `createSegmentsTable()` в `static/js/analytics-results.js` → новая `createSegmentsPanel(segments, timeMode)`.

**Не меняется:**
- API `/api/result-segments?result_id=...` — данные те же
- БД, модели, бэкенд — не трогаем
- Табы «Результаты по участкам» на странице результатов — отдельный UI

---

## Фильтрация данных (фронт, без нового API)

Из массива всех сегментов:

- **Последовательные отрезки** (`consecutiveSegments`): сегменты, где `from_km` одного = `to_km` предыдущего. Сортировка по `from_km` asc.
- **Сплиты от старта** (`splitSegments`): сегменты с `from_km === 0`, кроме Старт→Финиш (он идёт последним). Сортировка по `to_km` asc.
- **Нелинейные пары** (КТ1→КТ6 и т.п.) — отбрасываются.

## Компонент `createSegmentsPanel(segments, timeMode)`

Три части, рендерятся последовательно:

### 1. Бар-чарт `renderPaceChart(consecutiveSegments, timeMode)`

Входные данные: массив последовательных отрезков.

**Вычисления:**
```
pace_ms[i] = sg_time_clear_ms[i] / segment_km[i]   // или gun в зависимости от timeMode
min_pace = Math.min(...pace_ms)
max_pace = Math.max(...pace_ms)
ratio[i] = (pace_ms[i] - min_pace) / (max_pace - min_pace)  // 0=быстрый, 1=медленный
```

Если `max_pace === min_pace` → `ratio = 0` для всех (все зелёные).

**Высота бара:**
```
MAX_BAR_HEIGHT = 68px  // пиксели для самого медленного
MIN_BAR_HEIGHT = 14px  // пиксели для самого быстрого
height[i] = MIN_BAR_HEIGHT + ratio[i] * (MAX_BAR_HEIGHT - MIN_BAR_HEIGHT)
```

**Цвет** — линейная интерполяция RGB по `ratio[i]`:
- `ratio=0` → `#4caf50` (зелёный, быстрый)
- `ratio=1` → `#ef5350` (красный, медленный)
- Промежуточные: `r = 76 + ratio*(239-76)`, `g = 175 + ratio*(83-175)`, `b = 80 + ratio*(80-80)`

**Разметка каждого бара** (снизу вверх в DOM):
```
[диапазон км]       ← font-size:7px, color:#555, всегда серый  "5.3–8.3 км"
[темп мин/км]       ← font-size:8px, color=barColor, bold       "3:09 мин/км"
[бар]               ← background=barColor, height=height[i]px
[время / дистанция] ← font-size:8px, color=barColor (время bold, дистанция #666)
```

### 2. Таблица «Отрезки»

Заголовок-разделитель: `ОТРЕЗКИ` (красный `#e63946`).  
Колонки: Участок | Время | Темп | Абс. | Пол | Кат.  
Строки: `consecutiveSegments`, время и темп зависят от `timeMode`.

### 3. Таблица «Сплиты от старта»

Заголовок-разделитель: `СПЛИТЫ ОТ СТАРТА` (синий `#4a9eff`).  
Те же колонки.  
Строки: `splitSegments`.

## Граничные случаи

| Ситуация | Поведение |
|----------|-----------|
| 5км с 1 КТ (Весна) | Чарт из 2 баров, относительная шкала по 2 значениям |
| Участник не дошёл до КТ | `sg_time_clear = null` → отрезок пропускается в чарте и таблице |
| Нет ни одного последовательного отрезка | Чарт не рендерится; только сплиты (Старт→Финиш) |
| Все отрезки одного темпа (ratio=0) | Все бары зелёные, одинаковой высоты (`MIN_BAR_HEIGHT`) |
| Тоггл gun/net | `timeMode` передаётся в `createSegmentsPanel`; пересчитываются высоты, подписи темпа и времени |
