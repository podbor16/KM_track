# Дуатлон 222 — графики «Позиция» и «Темп/Скорость»

Дата: 2026-09-04

## Контекст и цель

На странице результатов Дуатлона 222 (`duathlon_results.html`) есть вкладки
«Итоги гонки» / «Бег-1» / «Вело» / «Бег-2», но нет визуализации динамики
гонки во времени/по дистанции. У Siberman (`templates/siberman/results.html`,
`static/js/siberman-common.js`) такая визуализация уже реализована — вкладка
«График» с двумя режимами (Позиция, Темп/Скорость), сайдбаром/bottom-sheet
для выбора участников и режимами «спагетти»/«сравнение».

Цель — перенести эту функциональность в Дуатлон 222, адаптировав под его
более простую структуру: 3 этапа в один день (Бег-1 10 км → Вело 170 км →
Бег-2 42 км), без дней и без эстафет, только личный зачёт М/Ж.

## 1. Точка входа

Новая вкладка **«График»** — пятая в `#page-tabs`, после «Бег-2»:

```
Итоги гонки | Бег-1 | Вело | Бег-2 | График
```

Существующий общий фильтр пола (Все/Мужчины/Женщины, `#gender-filter-group`)
продолжает действовать и на вкладке «График» без изменений.

Внутри вкладки, сверху вниз:
1. Переключатель режима: **Позиция** / **Темп-скорость** (`chartModeSwitchHtml`-паттерн — `filter-group` с двумя кнопками, активная подсвечена).
2. Фильтр этапа (свой список опций для каждого режима — см. разделы 3 и 4).
3. Область графика (canvas, Chart.js, уже подключён как `/static/lib/chart4/chart.umd.min.js`) + сайдбар выбора участников (десктоп) / кнопка-триггер bottom-sheet (мобилка).

## 2. Данные для графика

`get_standings()` в [src/duathlon222/service.py](../../../src/duathlon222/service.py)
получает новое поле на каждого участника — `"checkpoints"`:

```python
"checkpoints": {
    "run1": [{"lap": 1, "km": 1.25, "elapsed_s": 312}, ...],
    "bike":  [{"lap": 1, "km": 3.4,  "elapsed_s": 612}, ...],
    "run2":  [{"lap": 0, "km": 0.02, "elapsed_s": 15420}, ...],
}
```

- `km` — километраж внутри этапа, через уже существующий `_lap_distance_km(stage_code, lap_number)` (учитывает `IRREGULAR_LAP_KM` и `STAGE_LAP_OFFSET`).
- `elapsed_s` — накопленное время **от старта гонки** (не сплит внутри этапа) — единая шкала, удобная и для ранга (Позиция), и для дельт темпа (Темп/Скорость).
- Только отметки, которые участник реально прошёл (`elapsed_s is not None`), без плейсхолдеров на будущее.

Источник — уже вычисляемая внутри `get_standings()` структура `laps_by_key`
(строится для `_live_gap_map` и сейчас выбрасывается после использования) —
поле `checkpoints` сохраняет её в ответ вместо повторного похода в БД.

Km уже посчитан бэкендом на Python — на клиенте формулы дистанций
(`LAP_KM`/`STAGE_LAP_OFFSET`/`IRREGULAR_LAP_KM`) не дублируются. Это
осознанное отличие от Siberman, где `CHECKPOINT_DIST_KM` захардкожен в JS
отдельно от Python-стороны — здесь такого расхождения не будет.

Расход трафика: ~15 участников × ~75 точек × 2 числа ≈ единицы КБ на
30-секундный опрос — пренебрежимо для текущей нагрузки.

## 3. График «Позиция»

- **Фильтр этапа**: `Вся гонка` (по умолчанию) / `Бег-1` / `Вело` / `Бег-2`.
- **Ось X**:
  - В режиме одного этапа — реальные км этого этапа (0 → 10/170/42).
  - В режиме «Вся гонка» — виртуальные «раздутые» сегменты фиксированной
    ширины независимо от реальных км: **Бег-1 25%, Вело 50%, Бег-2 25%**.
    Иначе Бег-1/Бег-2 (10 и 42 км из 222 общих) визуально схлопнутся в
    нечитаемые полоски рядом с Вело (170 км). Границы этапов — пунктирные
    вертикальные линии + подпись км, рисуются кастомным Chart.js-плагином
    (аналог `stageBoundaryPlugin`), только в режиме «Вся гонка».
- **Ось Y** — **место (ранг)** участника в этой точке дистанции, не время.
  `reverse: true` (1-е место сверху). Ранг считается на клиенте: для каждой
  km-точки сортируются все участники по `elapsed_s`, кто её уже достиг.
  Диапазон Y — по фактически показанным рангам (не по всему составу), с
  пропорциональным отступом.
- **Режимы отображения**:
  - «Спагетти» (по умолчанию) — все линии тонкие/приглушённые
    (`--chart-context`), при наведении курсора подсвечивается ближайшая
    линия (не ближайшая точка — геометрический hit-test по интерполяции
    между соседними отметками, как `nearestDatasetIndexAtPixel` у Siberman) +
    подпись «имя — место» рисуется прямо на канвасе рядом с курсором.
  - «Сравнение» — включается выбором участников в сайдбаре/bottom-sheet или
    кликом по линии; показывает только выбранных, свои цвета (детерминированные
    по номеру участника, `chartCompareColor`), настоящая легенда Chart.js.

## 4. График «Темп/Скорость»

- **Фильтр этапа** — отдельная строка от общего переключателя режимов:
  `Бег-1` (по умолчанию) / `Вело` / `Бег-2`. Режима «вся гонка» здесь нет —
  темп (мин/км) и скорость (км/ч) физически нельзя показать одной шкалой Y.
- **Ось X** — реальные км выбранного этапа (0 → 10/170/42).
- **Ось Y**:
  - Бег-1/Бег-2: темп, мин/км, `reverse: true` (быстрее = выше на графике).
  - Вело: скорость, км/ч, без реверса (быстрее уже само по себе выше).
  - `grace: '8%'` — запас по Y, чтобы не обрезать крайние точки.
- **Точки** — сплит-значение между двумя соседними отметками участника:
  берётся дельта `elapsed_s` и дельта `km` между соседними записями массива
  `checkpoints[stage]`, переводится в темп/скорость на клиенте (та же логика,
  что `_lap_split_distance_km`/`speed_kmh` на бэкенде для одного участника —
  здесь пересчитывается из уже присланных cumulative-точек, чтобы не тянуть
  с бэкенда персональный сплит-эндпоинт для каждого участника разом).
- Экстраполяция линии горизонтально до X=0 на уровне темпа первой отметки —
  только для читаемости (старт этапа), не как измеренное значение.
- «Спагетти»/«сравнение» и hover — та же логика и тот же shared hit-test,
  что в «Позиции».

## 5. Выбор участников (сайдбар / bottom-sheet)

Прямой перенос Siberman-паттерна:

- **Десктоп** (`>640px`): сайдбар слева от графика — поиск по имени,
  чекбокс-список (сорт. по фамилии), кнопка «Выбрать всех/Очистить всех»
  (учитывает текущий текст поиска — действует только на видимых), подсказка
  «Выберите участников для сравнения», пока ничего не выбрано.
- **Мобилка** (`≤640px`): кнопка-триггер над графиком («Выбрать участников
  для сравнения» / «Сравниваю: N участников») открывает bottom-sheet снизу —
  тот же поиск/список/кнопка «всех» + кнопка «Готово». Клик по затемнённому
  фону закрывает; скролл страницы блокируется, пока открыт лист.
- Один общий `_chartSelectedBibs` для обоих режимов графика (Позиция и
  Темп/Скорость) и для всех фильтров этапа — не сбрасывается при
  переключении режима/этапа, только явным снятием выбора.
- Клик по линии на самом графике (не на тач-устройствах — там тап показывает
  значение в точке, а не переключает выбор) тоже добавляет/убирает участника
  из сравнения — то же действие, что чекбокс в сайдбаре.

Осознанное упрощение относительно Siberman — не перенос кода, а его
отсутствие за ненадобностью: нет логики эстафет/команд (`relay`, `team_name`,
`relay_stage`) и нет разбиения этапа Вело на день1/день2 — у Дуатлона 222
такой структуры просто не существует.

## Что не входит в эту задачу

- Города участников (отдельный пункт бэклога, отложен ранее).
- Изменение самих формул дистанции/лапов (`LAP_KM`, `STAGE_LAP_OFFSET`,
  `IRREGULAR_LAP_KM`) — используются как есть, уже исправлены в этом сезоне.
