# Личный кабинет, этап Б3: «Найти себя» и обращения — дизайн

Дата: 2026-11-04. Статус: согласован с пользователем (brainstorming), ждёт ревью спецификации.
Продолжение Б1 (`2026-11-03-athlete-cards-history-design.md`) и Б2 (`2026-11-04-athlete-reps-design.md`).

## Цель

1. Человек, которого записывали с чужой почты, находит свою карточку по ФИ + ДР + номеру и заявляет её «Это я».
2. Спор за карточку и «это не мой забег» — не письмом на почту, а **обращением** в одну очередь админки, где
   оператор решает с карточкой и строкой под рукой; человек получает письмо о решении.

## 1. «Найти себя»

- На `/me` — ссылка «Не нашли себя? Найти по данным» → `/me/find`: фамилия, имя, дата рождения, стартовый номер
  с любого своего забега (`POST /me/find`).
- Совпадение: карточка `clients` с точно такими ФИ (коллация БД: регистр и ё/е не важны — как `uk_client`) и ДР
  (не заглушка), у которой этот номер есть в каком-то забеге — `results.start_number` или `leads.start_number`
  строк этой карточки. Ровно одна карточка → «Это вы: {ФИ}, бегает с {год}, {N} стартов» и кнопка «Это я»
  (`POST /me/find/claim` с токеном находки, не с `client_id` из формы).
- Иначе (нет / несколько) — одинаково: «Не нашли — проверьте данные или отправьте обращение» (ссылка на форму
  обращения «Не могу найти себя»); какое поле не совпало — не раскрывается.
- Лимит: **5 поисков в сутки** на аккаунт (своя таблица попыток или общая `athlete_claim_attempts` с отдельным
  видом — без смешения с лимитом ДР).
- Общий лимит: **10 поисков в сутки по одной паре «фамилия + имя»** (strip, нижний регистр, ё→е) со всех аккаунтов —
  в `athlete_find_attempts.fio`; превышение любого лимита — один `FindLimit` и один текст.
- Заявление после поиска — те же проверки, что у «Это я» (п.2–6 Б1: уже ваша / заявлена другим → обращение-спор /
  без ДР / одна ДР у «это я» / лимит / сверка ДР), **кроме п.1** (заявка на почте): доказательство — номер.
  Токен находки — подписанный (HMAC `SECRET_KEY`) `client_id + email + срок 15 минут`, чтобы заявить можно было
  только найденную этим аккаунтом карточку.
- Только для себя: представителем через поиск стать нельзя.
- Журнал: `athlete_claim` с пометкой `via=find`.

## 2. Обращения

**Типы:** `dispute` — «Это моя карточка» (карточка уже заявлена другим аккаунтом); `wrong_row` — «Это не мой
забег» (строка результата или заявки в истории); `not_found` — «Не могу найти себя» (после неудачного поиска,
с введёнными ФИ/ДР/номером).

**Кабинет:**
- Спор: при ошибке `taken` у формы «Это я» (и после поиска) — вместо «напишите нам» кнопка «Это моя карточка —
  отправить обращение» (комментарий необязательный).
- Ошибка: у каждой строки результата и заявки в истории (своей и подопечного) — «Это не мой забег» →
  обращение со ссылкой на строку (комментарий необязательный); ссылка `mailto:` «Сообщить об ошибке» внизу
  истории заменяется на это.
- После отправки: «Обращение отправлено, ответим письмом на {почта}».
- Ограничения: **не больше 3 открытых обращений** на аккаунт; комментарий ≤ 1000 символов; одно открытое
  обращение на (аккаунт, карточка/строка, тип) — повтор не создаёт новое.

**Админка — вкладка «Обращения»** (счётчик новых; фильтр «новые / закрытые»). В обращении: тип, дата, почта
аккаунта, карточка (ссылка «Качество данных» → человек), строка (для `wrong_row`), введённые данные
(`not_found`), комментарий. Действия:
- `dispute`: **«Передать заявителю»** — привязка «Это я» переходит к заявителю (ДР привязки — ДР карточки),
  прежний владелец получает письмо «Карточка {ФИ} передана другому аккаунту по решению организаторов. Если это
  ошибка — ответьте на это письмо или напишите на 1@krasmarafon.ru»; представители карточки остаются;
  **«Отклонить»**.
- `wrong_row` / `not_found`: оператор правит существующими инструментами («Качество данных»: перенести строку,
  исправить, заявить — для `not_found` можно «Привязать карточку №… к заявителю»), затем **«Закрыть»**.
- У любого действия — необязательный **ответ оператора**; заявитель получает письмо: тема «Ваше обращение
  рассмотрено», текст — решение («Карточка привязана к вашему кабинету» / «Обращение отклонено» / «Обращение
  закрыто») + ответ оператора.
- Журнал `dq_actions`: `athlete_request` (создание), `athlete_request_resolve` (решение, кто, ответ),
  передача — `athlete_unclaim`/`athlete_claim` с причиной `dispute`.

## Данные

Миграция `migrations/athlete_requests.sql` (идемпотентно, без «;» в комментариях):

```sql
CREATE TABLE IF NOT EXISTS athlete_requests (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  email VARCHAR(255) NOT NULL,
  kind VARCHAR(16) NOT NULL,
  client_id INT NULL,
  row_table VARCHAR(16) NULL,
  row_id BIGINT NULL,
  payload JSON NULL,
  comment VARCHAR(1000) NULL,
  status VARCHAR(16) NOT NULL DEFAULT 'new',
  resolution VARCHAR(16) NULL,
  answer VARCHAR(1000) NULL,
  resolved_by VARCHAR(255) NULL,
  resolved_at DATETIME NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_areq_status (status, created_at),
  KEY idx_areq_email (email, status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS athlete_find_attempts (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  email VARCHAR(255) NOT NULL,
  fio VARCHAR(255) NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_afa (email, created_at),
  KEY idx_afa_fio (fio, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## Код

- `src/krasmarafon/services/athlete_find.py` — поиск, лимит, токен находки.
- `src/krasmarafon/services/athlete_requests.py` — создание (лимиты, дедупликация), список для админки, решения
  (передать / отклонить / закрыть), письма (в фоне).
- `athlete_claims` — заявление без п.1 для поиска и передача по спору (переиспользовать `_claim`/`unclaim_row`
  с флагом, без копипаста).
- Роутер кабинета: `/me/find` (GET/POST), `/me/find/claim`, `POST /me/request`; шаблоны `me-find.html`, кнопки в
  `me.html`/`me-history.html`. Админка: эндпоинты `/api/admin/athlete-requests…` (`api_require_auth`), вкладка
  в `admin.html` + JS (данные в DOM — `textContent`).
- Все POST — проверка Origin; всё под переключателем «Личный кабинет».

## Тесты

Интеграция (только тестовые данные): поиск — совпадение, нет/несколько (одинаковый ответ), лимит 5, токен (чужой /
просроченный / подделанный), заявление после поиска со всеми проверками; обращения — каждый тип, лимит 3,
дедупликация, длина комментария; админка — список, передача по спору (привязка перешла, письмо прежнему владельцу,
представители на месте), отклонить/закрыть с ответом (письмо заявителю), 401 без входа; журнал. Скриншоты
`/me/find`, кнопки обращений, вкладка админки (1280/390); ручная проверка; выкладка — после «да».

## Вне рамок

Переписка внутри обращения (только один ответ оператора); вложения; автоматическое исправление строк по
обращению.
