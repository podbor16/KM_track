# Личный кабинет, этап Б1: «Это я» и история спортсмена — дизайн

Дата: 2026-11-03. Статус: согласован с пользователем (brainstorming), ждёт ревью спецификации.
Продолжение этапа А (`2026-11-03-athlete-login-design.md`: вход по коду, `/me` по людям, скрытый запуск).
Схема «аккаунт ≠ спортсмен» — Obsidian `inbox/2026-11-03-krasmarafon-athlete-auth`.
Этап Б разбит: **Б1** (этот документ) — «Это я» + история; **Б2** — представители; **Б3** — поиск себя по
ФИ+ДР+номеру, споры в админке, обработка «сообщить об ошибке».

## Цель

Аккаунт (почта) заявляет карточку спортсмена (`clients.id`, «client_id») как свою, подтвердив дату рождения,
и видит полную историю: все забеги и заявки карточки — с любых почт, — итоги, рекорды, темп, динамику.

## Решения (пользователь, 2026-11-03)

- Итоги истории — все четыре блока: счётчики, личные рекорды, средний темп, динамика по годам
  (исторические результаты на проде загружены; локальный снимок может быть неполным).
- Одному аккаунту можно заявить **несколько** карточек «это я» (дубли склейки) — каждую с проверкой ДР;
  история объединённая; в админке — подсказка о возможном дубле.
- История — **отдельная страница**, компоновка **H1**: одна лента (итоги сверху, забеги и заявки по годам).
- Карточка уже заявлена другим аккаунтом → «напишите нам» (споры — Б3), кто заявил — не раскрываем.

## Заявление карточки («Это я»)

На `/me` у группы-человека с `client_id` (этап А: группа = `leads.client_id`) — кнопка **«Это я»**.
По нажатию раскрывается поле «Ваша дата рождения» (`<input type="date">`) и «Подтвердить»
(`POST /me/claim`, поля `client_id`, `birthday`). Сервер проверяет по порядку:

1. Карточка есть среди заявок этой почты (`leads.email`/`ma_email` = почта аккаунта, `leads.client_id` = карточка);
   иначе 404 (заявить чужую карточку по номеру нельзя — поиск по ФИ будет в Б3).
2. Карточка уже заявлена этим аккаунтом → редирект на историю.
3. Карточка заявлена другим аккаунтом → «Эту карточку уже заявили — напишите нам».
4. У карточки нет ДР (`clients.birthday` NULL или `1900-01-01`) → «Подтвердить не получится — напишите нам».
5. Лимит: 5 неверных попыток на (аккаунт, карточку) за сутки → «Попробуйте завтра или напишите нам».
6. ДР совпала → карточка закреплена, уведомление (ниже), редирект на `/me` с плашкой; не совпала →
   «Дата не совпадает» + запись попытки.

После заявления у человека на `/me` вместо кнопки — плашка **«Это вы · История →»** (`/me/history`).

**Отвязка:** внизу истории — «Это не моя карточка — отвязать» у каждой заявленной карточки
(`POST /me/unclaim`, `client_id`) с подтверждением `confirm()`.

**Уведомление** при заявлении: письмо на все различные почты из заявок карточки (`leads.email`, `ma_email`),
кроме почты аккаунта: тема «Вашу историю забегов привязали к личному кабинету», текст — «Историю забегов
{ФИ карточки} на сайте результатов Красмарафона привязали к почте {маска, напр. p***@mail.ru}. Если это
не вы — напишите нам на 1@krasmarafon.ru». Отправка — `send_mail` этапа А (на проде пока лог), ошибки
отправки не мешают заявлению (лог). Не больше 10 адресатов на карточку.

## Страница истории `/me/history`

Только своя (объединённая по всем заявленным карточкам аккаунта); без сессии → `/me/login`; нет заявленных
карточек → `/me`. (Адрес `/me/athlete/{client_id}` — для представителей в Б2.) Компоновка H1, макет —
`.superpowers/brainstorm/1478-1793707115/content/history-layout.html` (локально, не в git).

**Шапка:** «← Личный кабинет», ФИ (из самой новой заявленной карточки), «Бегает с {год первого старта}».

**Данные:** результаты `results.client_id IN (заявленные)` + заявки `leads.client_id IN (заявленные)`,
`is_duplicate = 0`. Флаг «Без ПД» не действует (свои данные). Заявка с результатом (тот же
`event_id + start_number`) показывается одной строкой — результатом. Время результата — `time_clear_finish`,
иначе `time_gun_finish`; место в категории — `rank_category_clean` при чистом времени, иначе `rank_category`.
Дистанция — `events.event_distance` (км, decimal).

**Итоги (сверху):**
- плитки: **стартов** (результаты со статусом ≠ `Not started`), **финишей** (`Finished` со временем),
  **км** (сумма дистанций финишей, округление до целого), **ср. темп** (суммарное время финишей /
  суммарные км, «м:сс»; дистанции < 1 км не учитываются);
- **личные рекорды**: по каждой дистанции с финишем — лучшее время, темп /км, событие и год; дистанции по
  убыванию;
- **динамика**: чипы дистанций, у которых финиши в ≥ 2 разных годах; график (Chart.js из
  `static/lib/chart4`) — лучшее время дистанции по годам; по умолчанию — дистанция с наибольшим числом
  финишей. Нет ни одной такой дистанции — блок не показывается.

**Лента «Забеги и заявки»** — по годам, новые сверху:
- предстоящие заявки — «билетом» как на `/me` (правило «предстоящая» — как в этапе А);
- результаты — строкой: событие · дистанция, дата, «протокол» / «диплом» (как в этапе А); справа время,
  под ним место в категории и темп;
- статусы без времени — серым: `Not started` и прошедшая заявка без результата → «не стартовал»;
  `DNF`/`Withdrawn` → «сошёл»; `DSQ` → «дисквалифицирован»; возврат → «возврат».

**Внизу:** «Нашли чужой забег? Сообщить об ошибке» — `mailto:1@krasmarafon.ru` с темой
«Ошибка в истории, карточка №…» (обработка в админке — Б3); «Это не моя карточка — отвязать».

## Админка

В `/admin`, рядом с переключателем «Личный кабинет», блок **«Кабинет: возможные дубли»** — аккаунты с
≥ 2 заявленными карточками: почта, номера карточек и их ФИ (ссылки в «Качество данных» → человек по
номеру, если такой экран есть). Только просмотр; склейка — существующими инструментами.

## Данные

Миграция `migrations/athlete_claims.sql` (идемпотентно):

```sql
CREATE TABLE IF NOT EXISTS athlete_claims (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  email VARCHAR(255) NOT NULL,
  client_id INT NOT NULL,
  birthday DATE NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uq_ac_client (client_id),
  KEY idx_ac_email (email)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS athlete_claim_attempts (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  email VARCHAR(255) NOT NULL,
  client_id INT NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_aca (email, client_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

`UNIQUE (client_id)` — одна карточка — один владелец; гонку двух аккаунтов решает БД (вторая вставка →
«уже заявили»). Заявление/отвязка — в журнал `dq_actions` (`action` = `athlete_claim` / `athlete_unclaim`,
`finding_key` = `client:{id}`, `done_by` = почта) — для разбора споров в Б3.
В `athlete_claims` хранится и **подтверждённая ДР** (`birthday DATE NOT NULL` — та, что ввёл человек).

**Правки в «Качестве данных»** (решение пользователя 2026-11-03). История не копируется — она собирается
на лету из того, что сейчас записано на карточке. Для привязки — **одно общее правило**:

> Привязка действует, пока карточка существует **и** её ДР (`clients.birthday`) совпадает с подтверждённой
> ДР привязки. Проверка — каждый раз при открытии `/me` и `/me/history` (`claimed_cards(email)`):
> недействительные привязки удаляются, запись в журнал (`athlete_unclaim`, причина `card_deleted` /
> `birthday_changed`), на `/me` у человека — «Данные карточки изменились — подтвердите, что это вы» и снова
> кнопка «Это я».

| Действие в админке | Что увидит человек |
|---|---|
| Перенос результата/заявки на другую карточку (`move_row`; пример: детский результат ошибочно на взрослом Иванове 1986 → на Иванова 2018) | строка пропала/появилась в истории |
| Правка строки результата/заявки (ФИ, ДР, пол, категория, дистанция) | исправленные данные в истории |
| Правка ФИ карточки | ничего не меняется |
| Правка ДР карточки | снова «Это я» — подтвердить новую ДР |
| Склейка, итоговая ДР та же | привязка переходит на итоговую карточку |
| Склейка, итоговая ДР другая | снова «Это я» |
| Карточка опустела и удалена | привязки нет |
| Отмена действия в журнале | то же правило по результату отмены |

Единственная точка в коде «Качества данных» — **склейка** (`dq_actions.merge_cards`): в той же транзакции
привязки удаляемых карточек переводятся на итоговую (`UPDATE athlete_claims SET client_id = итоговая`),
если итоговая ещё не заявлена; если заявлена — привязка удаляемой снимается (журнал). Дальше работает общее
правило ДР. Отмена склейки привязку обратно не переносит (человек при необходимости заявит восстановленную
карточку заново).

## Код

- `src/krasmarafon/services/athlete_claims.py` — заявление/отвязка/проверки/лимит/уведомление,
  `claimed_cards(email)`.
- `src/krasmarafon/services/athlete_history.py` — выборка и расчёт итогов (чистые функции над строками
  результатов/заявок — unit-тесты).
- `src/krasmarafon/routers/athlete.py` — `/me/claim`, `/me/unclaim`, `/me/history` (под тем же
  переключателем «Личный кабинет»); `/me` — флаги заявленности для групп.
- Шаблоны `me.html` (кнопка/форма/плашка), новый `me-history.html`; стили — `static/css/me.css`.
- Админка — эндпоинт + блок в `admin.html`.

## Ошибки и граничные случаи

- Неверный формат даты → «Проверьте дату».
- Карточку правили, склеили или удалили после заявления → общее правило раздела «Данные».
- У заявленной карточки нет результатов → итоги не показываются, только заявки.
- Две вкладки: заявить одну карточку дважды — редирект на историю (идемпотентно).

## Тесты

- Unit: расчёт итогов (счётчики, км, темп без дистанций < 1 км, рекорды, динамика ≥ 2 лет, статусы,
  слияние заявки с результатом).
- Интеграция (локальная БД): заявление с верной/неверной ДР, лимит 5/сутки, чужая карточка (404),
  уже заявленная другим, без ДР, несколько карточек, отвязка, журнал, уведомление (адресаты без почты
  аккаунта), доступ к `/me/history` (сессия, переключатель), блок дублей в админке; перенос строки на другую карточку — пропадает из истории прежнего
  владельца; склейка с той же ДР — привязка переходит, с другой ДР или на чужую заявленную — снимается
  (журнал); опустевшая удалённая карточка — привязка снимается; правка ДР карточки — привязка снимается,
  правка ФИ — остаётся; пояснение «Данные карточки изменились» на `/me`.
- Скриншоты `/me` и `/me/history` (десктоп и 390px) перед передачей пользователю.
- Ручная проверка пользователем локально; выкладка — после его «да».
