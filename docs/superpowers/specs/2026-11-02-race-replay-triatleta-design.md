## 2. Песочница и обезличивание

- `<db>_demo` пересоздаётся из локальной `<db>` (все таблицы). Только локальная БД :3308.
- Имена БД зашиты в прод-коде (`src/race_triatleta/db.py`, `src/duathlon222/db.py`): на время сборки подменяется функция подключения, которую импортирует `service` (`service.get_tri_connection` / `service.get_duathlon_connection`) — она открывает только `*_demo` и падает на любом другом имени.
- Обезличивание: ФИО → сгенерированные (пол сохранён; словари `tools/demo/anonymize.py`); Триатлет: участники с `gender='mixed'` (команды — название в `surname`) и `team_name` → «Команда N», `birthdate` → NULL; Дуатлон: `city`, `country` → пусто/NULL; номера перемешиваются (детерминированно).

## 3. Проигрывание

- Итоговые данные читаются в память; таблицы результатов песочницы очищаются (Триатлет: `laps`; Дуатлон: `checkpoints`, колонки этапов участников → NULL), статусы → активный.
- Шкала — секунды от выстрела, окно [−300 с; последняя отметка + 300 с], шаг 30 с (= темп прод-загрузчиков).
- На шаге T прямым SQL с итоговыми значениями дописывается всё, что ≤ T: Триатлет — `laps` с `cumulative_ms ≤ T`; Дуатлон — `checkpoints` с `cumulative_s ≤ T` и колонки этапов/транзитов, у которых момент ≤ T (`run1_s`, `t1_s`, `bike_start_s`, `bike_s`, `t2_s`, `run2_start_s`, `run2_s` — моменты окончания этапов от выстрела по их смыслу; уточнить по загрузчику и сервису). Статус «финишировал» — с момента финиша; DNF/DSQ — с момента последней отметки участника (если отметок нет — с выстрела).
- Ответы на шаге — прод-функции сервисов: Триатлет `get_standings(1, None)`, `get_all_laps(1)`; Дуатлон `get_standings(event_id, None|'M'|'F')`, `get_participant(event_id, n)` для каждого номера. Сериализация — как в роутерах.
- Запись: `{meta, initial, changes}`; ответы — по ключу эндпоинта (`standings`, `standings?gender=M`, …, `participant/<n>`, `laps`); списки — diff по ключу элемента (`start_number`, круг — `participant_id`+`lap_number`), с порядком; прочие ключи — целиком.
- Точность: в конце повтора все ответы == ответам прод-кода по полным итоговым данным.

## 4. Браузер и сайт

- `demo-replay.js`, режим `poll`, обобщается: окна (`data-days`) могут быть одним окном; карта эндпоинтов → ключ записи (с учётом `?gender=`); адаптер ссылок на карточку (`/duathlon222_2026/participant/<n>` → `${BASE}duathlon222-2026/participant/<n>/?t=&speed=`); функции обновления страницы при перемотке вперёд (`loadStandings`/`loadLaps`/`load`, если есть). Siberman и Жара — без регрессий.
- Отметки ползунка: Триатлет — «Старт», «6 ч», «12 ч», «18 ч», «Финиш», старт повтора — 2-й час; Дуатлон — «Старт», «Вело», «Бег 42 км», «Финиш» (моменты из данных: первое начало этапа), старт повтора — середина вело.
- Витрина: две карточки. Сборка: `build.py … triatleta_24h duathlon222_2026`. Проверки ПДн — плюс команды, города, фамилии из `/api/tri/laps`.
