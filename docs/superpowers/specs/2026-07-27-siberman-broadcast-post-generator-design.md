## Контекст

Команда трансляции Siberman вручную готовит текстовые посты для соцсетей с расстановкой участников на конкретной точке гонки. Раньше (суточная велогонка Triatleta) для этого уже есть генератор в `templates/race_triatleta/tri_admin.html` (таб «📋 Пост») — один клик генерирует ОДИН пост со всеми категориями по ТЕКУЩЕМУ live-состоянию гонки.

Siberman — многодневная гонка (плавание→вело1→вело2→бег), и посты нужны РАЗНЫЕ по смыслу:
- на конкретной, вручную выбранной контрольной точке (не обязательно "сейчас")
- с полным списком участников (не только топ-3) — команда трансляции сама решает нужный срез под ситуацию на трассе
- в двух принципиально разных разрезах: "место внутри этапа" и "виртуальное место по сумме всей гонки"

Полное исходное ТЗ пользователя (5 примеров постов, дословно) — [[inbox/2026-07-27-siberman-broadcast-post-generator]] в Obsidian. Ниже — уточнённая и расширенная по итогам брейншторминга архитектура.

## Часть 1 — Три режима генерации (один движок, не отдельный код на тип поста)

Все посты сводятся к трём параметризуемым режимам. Никакого нового backend-эндпоинта не требуется — всё строится на клиенте поверх уже загруженного `/api/siberman/results`, теми же функциями, что уже используют графики/таблицы `results.html`.

### Режим A — «По этапу»
Место/отставание **внутри выбранного этапа**, на выбранной КТ.

**Параметры:** Этап (Плавание / Вело День 1 / Вело День 2 / Вело оба дня / Бег) + КТ + Категория (Мужчины/Женщины/Эстафеты).

**Функции:** `computeCheckpointRanks(rows, dbStage, maxSeq)` / `computeCheckpointGaps(...)` для отдельных этапов; `computeBikeCombinedCheckpointRanks(rows)` для «Вело оба дня» (виртуальный сквозной seq день1→день2, уже используется графиком «Позиция»).

**Шаблон** — по образцу постов 1-3 из исходного ТЗ:
```
{КАТЕГОРИЯ}. {ЭМОДЗИ} {НАЗВАНИЕ ЭТАПА}. SIBERMAN 2026
📍 Контрольная точка: {N} из {ДИСТАНЦИЯ} км ({N} из {M} кругов/КТ).

Текущая расстановка на этапе:

1️⃣ {Фамилия Имя | Название команды (роль: Фамилия Имя)}
⏱️ Время на отметке {N} км: {Ч:ММ:СС} ({темп/скорость})
📊 Преимущество над 2-м местом: {значение}   ← у 1-го места
📊 Отставание от лидера: +{значение}          ← у остальных
```
Глагол роли эстафетчика по этапу (в скобках после названия команды): «плывёт» (Плавание), «едет» (Вело День 1/День 2/оба дня), «бежит» (Бег) — «плывёт»/«бежит» дословно из исходного ТЗ (посты 3/5), «едет» — по аналогии, для Вело.
Единицы по этапу (переиспользуем `paceValueLabel(dbStage, v)`, см. Часть 3): Плавание — темп /100м, Вело* — скорость км/ч, Бег — темп /км.

Эмодзи заголовка (уже используются в шапке таблицы «Итоги гонки», `results.html:769-772`): 🏊 плавание (🏊🏻‍♂️/🏊🏻 для М-Эстафеты/Ж — как в исходных шаблонах 1-3), 🚴 вело, 🏃 бег.

### Режим B — «По всей гонке» (виртуальный зачёт)
Место/отставание **по сумме всей гонки**, спроецированное на выбранную точку — тот же принцип, что уже считает график «Позиция → Вся гонка».

**Параметры:** Этап (Плавание / Вело День 1 / Вело День 2 / Бег — только РЕАЛЬНЫЕ этапы, не «оба дня», т.к. `globalProgress` работает с настоящим stage+seq) + КТ + Категория.

**Функции:** `computeGlobalCheckpointRanks`/`computeGlobalCheckpointGaps` (`globalProgress`, уже в `siberman-common.js`).

**Шаблон** — по образцу постов 4-5 из исходного ТЗ, обобщён на любой этап (не только бег):
```
{КАТЕГОРИЯ}. ЛИЧНЫЙ ЗАЧЁТ. SIBERMAN 2026        ← для М/Ж
{КАТЕГОРИЯ}. SIBERMAN 2026                        ← для Эстафет (без "ЛИЧНЫЙ ЗАЧЁТ")
📍 Контрольная точка: {N} из {ДИСТАНЦИЯ} км ({N} из {M} кругов/КТ) {ЭТАП в род. падеже} этапа.

Текущая расстановка по сумме трёх дней гонки.

1️⃣ {Фамилия Имя | Название команды (роль: Фамилия Имя)}
⏱️ {ЭТАП} на отметке {N} км: {Ч:ММ:СС} (темп/скорость)
📊 Виртуальное преимущество над 2-м местом: {значение}   ← у 1-го места
📊 Отставание от лидера: +{значение}                       ← М/Ж, остальные
📊 Отставание от лидеров: +{значение}                      ← Эстафеты, остальные
```
Фраза «по сумме трёх дней гонки» — фиксированная, как в исходном шаблоне (не зависит от того, на каком именно этапе сейчас точка).

### Режим C — «По дням» (снапшот на конец дня)
Отдельный пункт в UI (по явному решению пользователя), но реализован КАК ЧАСТНЫЙ СЛУЧАЙ режима B с зафиксированной точкой — не отдельная арифметика:
- «День 1» = режим B с `stage='bike_day1', seq=STAGE_MAX_SEQ.bike_day1` → это ровно существующая `day1Progress(row)` из `results.html:1081`.
- «День 1+2» = режим B с `stage='bike_day2', seq=STAGE_MAX_SEQ.bike_day2` → ровно существующая `day2Progress(row)`.

**Параметры:** День (День 1 / День 1+2) + Категория. КТ не выбирается — она зафиксирована на конец дня.

**Шаблон** (предложен по аналогии с режимом B — исходное ТЗ не давало пример для этого случая, **нужно подтвердить при ревью спеки**):
```
{КАТЕГОРИЯ}. ИТОГИ ДНЯ {1 | 1+2}. SIBERMAN 2026
📍 По итогам {первого дня | двух дней} гонки (плавание + вело{ День 1 | Дни 1-2}).

Текущая расстановка по сумме {дня | двух дней} гонки:

1️⃣ {Фамилия Имя | Название команды (роль: Фамилия Имя)}
⏱️ Итоговое время: {Ч:ММ:СС}
📊 Преимущество над 2-м местом: {значение}
📊 Отставание от лидера(ов): +{значение}
```

## Часть 2 — UI вкладки «Трансляция» (единая форма)

Одна форма вместо 11+ отдельных кнопок (по решению из брейншторминга):

1. **Режим:** [По этапу | По всей гонке | По дням] — радио/select
2. Контекстные поля (зависят от режима):
   - По этапу → select «Этап» (5 вариантов) → select «КТ» (список зависит от этапа, подписи — `CHECKPOINT_LABELS`, для «Вело оба дня» — новый маленький хелпер, объединяющий подписи дня1/дня2) → select «Категория» (Мужчины/Женщины/Эстафеты)
   - По всей гонке → select «Этап» (4 реальных этапа) → select «КТ» → select «Категория»
   - По дням → select «День» (День 1 / День 1+2) → select «Категория»
3. Кнопка «Сгенерировать» → `<textarea readonly>` с ПОЛНЫМ ранжированным списком + кнопка «Копировать» (тот же паттерн, что уже в `tri_admin.html`: `navigator.clipboard.writeText`, fallback — `select()`+`execCommand('copy')`)

Нумерация строк в полном списке: keycap-эмодзи 1️⃣-9️⃣ для мест 1-9 (как в исходных шаблонах), простое «10.», «11.»... для мест 10+ (keycap-эмодзи для двузначных чисел не существует единым глифом).

Участники без данных на выбранной КТ (ещё не дошли/DNF) — не включаются в список (тот же фильтр, что уже встроен в `computeCheckpointRanks`/`computeGlobalCheckpointRanks` — пропускают `val==null`).

## Часть 3 — Рефакторинг: `paceValueLabel`/`fmtSecClock` → `siberman-common.js`

Сейчас `paceValueLabel(dbStage, v)` и `fmtSecClock(v)` определены внутри `results.html` (используются только графиком). Генератору постов (в `admin.html`) они тоже нужны для форматирования темпа/скорости по этапам.

**Действие:** перенести обе функции в `static/js/siberman-common.js` (тело без изменений — чистое перемещение, не рефакторинг логики), убрать дубли из `results.html`, подключить `siberman-common.js` в `admin.html` (сейчас не подключён вообще).

**Риск:** `results.html` уже подключает `siberman-common.js` раньше своего inline-скрипта — порядок объявления не меняется, поведение `results.html` должно остаться побитово идентичным. Проверить: `paceValueLabel`/`fmtSecClock` не имеют closure-зависимостей от других переменных `results.html` (бегло проверено — обе функции чистые, зависят только от `fmtSpeed`/`STAGE_MAX_SEQ`, которые уже в `common.js`).
