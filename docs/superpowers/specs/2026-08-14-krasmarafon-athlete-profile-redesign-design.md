# Редизайн athlete-profile.html — дизайн

## Контекст

Четвёртый под-проект программы «Редизайн всего сайта Красмарафона, кроме
карточки над трекером и самого трекера» (см. `текущие приоритеты.md` →
КРАСМАРАФОН → Подготовка к Жаре, п.1). Программа охватывает 7-8 страниц —
`results.html`, `start_list.html` и `race-analysis.html` уже задеплоены.
Эта спека закрывает `athlete-profile.html`.

Страница сейчас скрыта флагом `history_enabled` (на время подготовки к
Жаре, вместе с `/history`) — по тому же принципу, что и `race-analysis.html`
(отдельно не в навигации, но полностью в основной), редизайним и деплоим
заранее, чтобы страница была готова к моменту, когда история снова
включится.

`athlete-profile.html` использует собственный CSS-файл
(`static/css/athlete-profile.css`) с паттернами, уже признанными
устаревшими и убранными на трёх предыдущих страницах: диагональные
градиенты (`.profile-header`, `.races-table thead`, `.error`,
`.extended-stats`, `.filters-container`), тяжёлые hover-подъёмы карточек,
select-фильтры в цветной панели вместо общего `.km-toolbar`.

Дизайн выбран через brainstorming с visual companion (сравнение вариантов
шапки профиля и карточки забега вживую в браузере) + текстовое
подтверждение переноса уже устоявшихся паттернов (фильтры, переключатель
вида, расширенная статистика, таблица) — та же логика, что уже применена
на `results.html`/`start_list.html`/`race-analysis.html`.

## Изменения

### 1. Шапка профиля (`.profile-header` → выбран вариант C)

Сейчас: сплошной розовый градиентный блок (`linear-gradient(135deg,
#EE2D62 0%, #d41451 100%)`) на всю ширину, имя + инфо-плашки
(`.info-item`, полупрозрачные, внутри блока).

Новый вид: белая карточка с акцентной полосой `--km-primary` слева (тот
же язык, что `.stat-card`/`.km-event-banner`), имя крупным шрифтом
(`--km-font-brand`), год рождения/пол/категория — компактные подписи
(лейбл + значение) в ряд справа/под именем, без сплошной цветной заливки.

### 2. Карточка забега в сетке (`.race-card` → выбран вариант B)

Структура остаётся как сейчас (дата, название события, дистанция-бейдж,
статус-плашка, время/темп/место, кнопка диплома) — JS-рендер
(`renderGridView()`) почти не меняется, меняется только CSS:
- Убрать `.race-card:hover { transform: translateY(-6px); ... }` — тяжёлый
  подъём заменить на лёгкое усиление тени без сдвига
- Тень по умолчанию — тоньше (`0 1px 3px rgba(0,0,0,.06)` вместо текущей
  `--km-shadow`)
- Кнопка диплома (`.diploma-link-btn`) — без изменений (сплошная розовая,
  на всю ширину)

### 3. Фильтры (Событие/Дистанция/Год)

Сейчас: `.filters-container` — панель с `linear-gradient(135deg, #f9f9f9
0%, #fafafa 100%)` фоном, `border-left: 4px solid var(--km-primary)`,
`.filter-select` внутри.

Новый вид: обычный `.km-toolbar` с тремя `.km-select` (тот же паттерн,
что `results.html`/`start_list.html`) — без панели-обёртки, без градиента.
`renderFilters()` в JS меняет только классы у существующих `<select>`
(`id="eventNameFilter"`/`id="distanceFilter"`/`id="yearFilter"` остаются
теми же id, обработчики те же), кнопка «Очистить фильтры»
(`.btn-filter-clear`) остаётся как есть (`.km-select` не отменяет
необходимость явной кнопки сброса — фильтров 3, не 1).

### 4. Переключатель Сетка/Таблица (`.view-toggle-btn` → `.km-pill`)

Сейчас: `.view-toggle-btn`/`.view-toggle-btn--active` — розовые кнопки с
обводкой, разметка `<button id="gridViewBtn">`/`<button id="tableViewBtn">`.

Новый вид: `.km-pills`/`.km-pill` — тот же компонент, что фильтр пола на
`results.html`/`start_list.html`. Два статичных pill-элемента (Сетка/
Таблица), переключение активного класса — та же логика, что
`_setGenderFilterActivePill()` там (переключить `.active`, без
пересборки DOM). JS-обработчики `renderResults()` меняют только то, как
проставляется активный класс — сама логика show/hide `#racesGrid`/
`#racesTableWrapper` не меняется.

### 5. Расширенная статистика (`.extended-stats`)

Сейчас: внешний контейнер — серый градиентный блок
(`linear-gradient(135deg, #f5f5f5 0%, #fafafa 100%)`) с
`border-left: 4px solid var(--km-primary)`, внутри — белые
`.extended-stat-item` карточки.

Новый вид (по прецеденту `race-analysis.html`, где то же самое —
`.stat-item`/`.best-result` — заменено на плоские белые карточки с
рамкой): убрать градиентный внешний контейнер целиком (фон/паддинг/
border-left), оставить только сетку `.extended-stat-item` карточек
(белый фон, тонкая рамка вместо тени, без внешней обёртки).

### 6. Таблица истории забегов (`.races-table`)

`.races-table thead` — убрать `linear-gradient(135deg, var(--km-primary)
0%, #d41451 100%)`, заменить на плоскую заливку `background:
var(--km-primary)` (тот же паттерн, что `.km-th` на
`results.html`/`race-analysis.html`).

### 7. Основная статистика и карточки графиков — точечное смягчение

`.stat-card`/`.chart-card` уже в целом в духе km-языка (белый фон,
акцент слева/рамка) — только убрать/смягчить hover-подъём
(`transform: translateY(-2px|-3px)`) до плоского усиления тени, без
сдвига (тот же принцип, что в п.2).

### 8. Попутный фикс

Дублирующийся закрывающий `</script>` в конце файла
(`templates/krasmarafon/athlete-profile.html`, текущие строки 894-895) —
убрать лишний тег.

### 9. Не в объёме этой спеки

- Логика графиков (Chart.js) и расчётов статистики — не меняются, только
  контейнер вокруг
- Сама структура данных/API (`/api/athlete/{surname}/{name}`) — не
  меняется
- Включение флага `history_enabled` — отдельное решение пользователя,
  не часть этой задачи
- Остальные страницы программы редизайна (`history.html`,
  `business-analytics.html`, `admin.html`) — отдельные будущие
  под-проекты

## Тестирование

- Полный прогон существующего Python test suite (страница не завязана на
  backend-логику, но регрессия по общим CSS-файлам должна быть
  исключена) — `conda run -n base python -m pytest tests/unit/ -q`
- Unit-тест на pill-логику переключателя Сетка/Таблица (`node:vm`, тот же
  паттерн, что уже используется для gender-пилюль на
  `results.html`/`start_list.html`) — переключение активного класса +
  вызов существующей логики показа/скрытия без побочных пересчётов
- Визуальная проверка в браузере (agent-browser) — десктоп и мобильная
  ширина, т.к. `/athlete-profile` скрыта флагом, потребуется временно
  включить `history_enabled` локально или открыть страницу с подставленной
  фикстурой `currentAthlete`/`currentResults` напрямую через
  `agent-browser eval` (тот же приём, что в плане `start_list.html`):
  - Шапка профиля — акцентная полоса слева, без цветной заливки
  - Карточки забегов — нет подъёма при наведении, тень тоньше
  - Фильтры — обычный `.km-toolbar`, без цветной панели
  - Переключатель Сетка/Таблица — pill-кнопки, кликабельны
  - Расширенная статистика — плоские карточки без внешнего градиентного
    контейнера
  - Таблица — плоский розовый `<thead>` без градиента
  - Мобильная ширина — ничего не переполняет экран горизонтально
