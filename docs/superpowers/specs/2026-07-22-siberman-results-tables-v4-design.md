# Спека: переработка главных таблиц results.html (п.7–9, v4)

**Дата:** 2026-07-22
**Статус:** Approved
**Страница:** `/siberman/results`

---

## Контекст

Живое использование графика/таблиц после деплоя v4-правок п.1-6,10 выявило три связанных пункта (п.7-9 из `knowledge/decisions/2026-07-22-siberman-results-v4-tasks.md`), затрагивающих один и тот же рендер-код (`renderOverall()`, `renderStage()`, `renderBikeCombined()`, `renderRankedProgress()`/Дни) — реализуются одним циклом.

Ключевая находка при разборе кода: у эстафеты на разных вкладках **разный смысл "пола"**:
- На «Итогах гонки» и «Днях» команда — цельная сущность без личного пола (три разных человека на трёх этапах).
- На вкладках этапов (Плавание/Вело1/Вело2/Бег) и на «Своде вело» строка эстафеты — это **конкретный человек** (пловец/велосипедист/бегун команды) с настоящим полом — код это уже учитывает (`stageGenderRanks`, `bikeCombinedRelayRider`).

Это разделение — основа всей архитектуры ниже.

---

## Часть 1 — Общий бейдж места (М1/Ж1/Э1)

`rankBodyCells(rankAbs, rankGender, gender, rc, teamLevel)` в `results.html` уже рендерит объединённый бейдж «буква+число» (`genderBadge(gender) + rankGender` → «М1»/«Ж1»). Расширяем на эстафету: когда строка — эстафета, вместо `genderBadge(gender)` подставляется бейдж «Э» того же вида (`<span class="letter e">Э</span>`), а число — не гендерный ранг, а **ранг по формату** (место среди только эстафетных команд/участников).

Новый параметр функции — `rankSecondary` (значение) + `secondaryBadgeLetter` ('М'/'Ж'/'Э') — заменяет текущую пару `(rankGender, gender)`, чтобы один и тот же рендерер работал и для пола, и для формата без дублирования кода.

`teamLevel=true` параметр **убирается** — раньше он схлопывал колонку в одну при `_fmt==='relay'` (у команды не было значения показать); теперь значение всегда есть (либо гендерный, либо форматный ранг), схлопывание не нужно нигде.

## Часть 2 — Командные таблицы: Итоги гонки, День 1, День 2

Строка = команда/личник целиком, без личного пола у команды.

**Убрать:** отдельные колонки «Пол» и «Формат».

**Добавить:**
- Бейдж рядом с именем: `badge-individual` «Индивидуальный» у личников (новый CSS-класс, копия из `participant.html`, туда уже добавлен в этой сессии), `badge-relay` «Эстафета» у команд (уже существует).
- Подсветка строки эстафеты — вариант C с брейншторминга: полупрозрачный синий фон (`rgba(106,171,215,.08)`) + полоска слева (`box-shadow: inset 3px 0 0 var(--blue)`). При пересечении с существующей подсветкой топ-3 (`tr.rank-1/2/3`, уже есть фоновые оттенки) — полоска слева остаётся основным индикатором эстафеты, фоны складываются (оба полупрозрачные, конфликта по факту не будет).
- Место (2 колонки, порядок как сейчас переключается по `_gender`/аналогично по `_fmt`):
  - `_fmt !== 'relay'`: Место (абсолют) | Пол/Формат — новое имя колонки вместо «По полу» (у личника «М1»/«Ж1», у команды «Э{ранг по формату}»)
  - `_fmt === 'relay'`: Место (формат) | Абсолют — та же логика swap, что уже работает для `_gender`, только формат вместо пола

**Новые вычисления** (мест в коде нет — добавляются):
- `relayFormatRanks = computeRanksByValue(relay.map(t => ({ key: t.bib, val: <метрика>, status: teamGapRow(t).status })))` — метрика: `overall_s` для Итогов, `day1Progress(teamGapRow(t))`/`day2Progress(...)` для Дней. Тот же паттерн, что уже есть в `participant.html:renderTeam()` для Итогов — переносится и обобщается на Дни.

## Часть 3 — Персонифицированные таблицы: этапы + Свод вело

Строка = конкретный человек (реальный пол уже вычисляется). Свод вело относится сюда, а не к части 2 — велоэтап эстафеты едет один и тот же человек оба дня, `bikeCombinedRelayRider()` уже строит по нему personal-like объект.

**Под «Все»/«Личный»:** без изменений — текущий 2-колоночный Место/Пол паттерн уже корректен и для личников, и для эстафетчиков (у них уже настоящий личный пол).

**Под «Эстафета»:** переключение на **3 отдельные колонки** — Формат | Пол | Абсолют (вариант A с брейншторминга):
- Формат — ранг СРЕДИ ТОЛЬКО эстафетчиков на этом конкретном этапе/своде (новое вычисление: `computeRanksByValue` над пулом, отфильтрованным только на эстафетных участников той же роли)
- Пол — ранг среди эстафетчиков своего пола на этом этапе (уже частично считается похожим образом в `stageGenderRanks`, обобщить на relay-only пул)
- Абсолют — уже существующий `stageAbsRanks`/`absRanks` (весь пул этапа, личники+эстафета вместе)

Под «Все»+«Все» на этих вкладках новый третий столбец **не показывается** — там продолжает работать обычный 2-колоночный паттерн, ничего не меняется относительно текущего поведения (личник и эстафетчик неотличимы по структуре колонок).

**Фильтр по полу (п.8):** сейчас скрывается везде при `_fmt==='relay'` (`render()`, `hideGender = _fmt === 'relay'`). Меняем условие:
```js
const PERSONIFIED_TABS = ['swim', 'run', 'bike']; // bike покрывает оба сабтаба (bike1/bike2) И combined/Свод
const hideGender = _fmt === 'relay' && !PERSONIFIED_TABS.includes(_tab);
```
На «Графике» и «Старте вело-2» фильтр по полу остаётся скрытым при эстафете — вне скопа этой правки (осознанно, подтверждено пользователем).

**Строки эстафеты** здесь тоже получают подсветку (Часть 2) — единообразно по всему сайту.

## Часть 4 — Дни (День 1 / День 2): добавить отставание + абсолют

Сейчас (`renderRankedProgress`/`buildProgressRow`) — только Место (без разделения абсолют/пол-формат в общем случае) + Время + Статус, отставания нет вообще.

**Новые колонки, 4 штуки, отдельными колонками (как на Итогах гонки):**

`Место (формат/пол) | Отставание (формат/пол) | Место (абсолют) | Отставание (абсолют)`

- «Место (формат/пол)» — ранг ВНУТРИ текущего активно отфильтрованного пула (та же величина, что уже есть — `genderRanks`/новый `relayFormatRanks` из Части 2), бейдж М1/Ж1/Э1.
- «Отставание (формат/пол)» — **новое**: разница `v[key] - v[leaderKey]` внутри того же пула, где `leaderKey` — участник с наименьшим `v` (уже отсортированы по возрастанию в `buildRankedEntries`). Простое вычитание, не требует `computeOverallGaps`/checkpoint-логики — `day1Progress`/`day2Progress` уже дают единое сравнимое число.
- «Место (абсолют)» — ранг среди ВСЕХ участников года (личники+эстафета вместе, без учёта текущих фильтров формата/пола) — тот же принцип, что `computeCombinedOverallRanks` на Итогах гонки, но по `day1Progress`/`day2Progress` вместо `overall_s`.
- «Отставание (абсолют)» — то же вычитание, но относительно лидера ПОЛНОГО ростера (не текущего фильтра).

Подсветка строк эстафеты и бейджи имени (Часть 2) — тоже применяются здесь.

**Намеренная асимметрия с Итогами гонки:** на Итогах остаётся ОДНА колонка «Отставание» (относительно абсолютного лидера, как сейчас) — пользователь не просил добавлять туда вторую пару «по формату/полу». Четыре колонки места+отставания — только на Днях, по явному запросу п.9. Не «выравнивать» с Итогами при реализации.

## Что НЕ входит в этот спек

- Фильтр по полу на «Графике» и «Старте вело-2» при формате «Эстафета» — остаётся скрытым, вне скопа
- Любые изменения `buildPositionDatasets`/графиков — они уже решены отдельным фоновым агентом в рамках текущей сессии, не пересекается с этой спекой
- Изменение самого алгоритма отставаний на Итогах/этапах (`computeOverallGaps`/`computeStageGaps`) — переиспользуется как есть

## Зависимости / затрагиваемые функции

`templates/siberman/results.html`:
- `rankHeaderCells()`, `rankBodyCells()` — переработка сигнатуры (пол→формат обобщение, убрать `teamLevel`)
- `buildIndividualOverallRow()`, `buildRelayOverallRow()`, `OVERALL_TABLE_HEAD` — убрать колонки Пол/Формат, добавить бейджи+подсветку, добавить `relayFormatRanks`
- `renderStage()` (`buildIndividualStageRow`, `buildRelayStageRow`) — новая ветка 3-колоночного режима под `_fmt==='relay'`, relay-only ранги (формат/пол), подсветка
- `renderBikeCombined()` — та же переработка, что и `renderStage()` (личный пол уже есть)
- `renderRankedProgress()`, `buildProgressRow()`, `buildRankedEntries()` (Дни) — 4 новые колонки (формат/пол-место+отставание, абсолют-место+отставание)
- `render()` — условие `hideGender` с учётом `_tab`
- CSS `<style>` в `results.html` — новый `.badge-individual`, стили подсветки строки эстафеты

`static/js/siberman-common.js`: возможно, `computeRanksByValue` переиспользуется как есть (уже общий примитив, изменений не требует).
