# Редизайн results.html (вариант C: полировка бренда) — дизайн

## Контекст

Первый под-проект программы «Редизайн всего сайта Красмарафона, кроме
карточки над трекером и самого трекера» (см. `текущие приоритеты.md` →
КРАСМАРАФОН → Подготовка к Жаре, п.1). Программа охватывает 7-8 страниц
(`results.html`, `start_list.html`, `history.html`, `athlete-profile.html`,
`race-analysis.html`, `business-analytics.html`, `admin.html`) — каждая
получит свой отдельный цикл спека→план→реализация. Эта спека закрывает
только `results.html`.

## Выбранное направление (вариант C)

Сравнили вживую 3 реальных стиля того же проекта (Siberman — тёмная
плотная, Triatleta — светлая минималистичная, текущий Красмарафон)
через brainstorming visual companion. Выбор пользователя: **сохранить
брендинг и цвета Красмарафона** (`--km-primary: #EE2D62`, шрифты
HouschkaRoundedAlt/HouschkaPro, светлая тема — уже определены в
`km-design-tokens.css`), но довести применение до современного вида —
не копировать тёмную тему Siberman.

Токены уже существуют и адекватны (радиусы, тени, цвета). Проблема — в
том, КАК они применены на `results.html`: пустой серый блок-баннер без
фото, диагональный градиентный хэдер таблицы (приём из 2015-х), dropdown
для пола вместо более современных pill-кнопок.

## Изменения

### 1. Карточка события (`.km-event-card`)

Сейчас: `position:relative` блок 180px высотой, `background-image` от
события (если задано в конфиге) + затемняющий `.km-event-card__overlay`
+ плавающая полупрозрачная панель `.km-event-card__controls` с
селекторами Событие/Год. Для событий без сконфигурированного фото (напр.
«Достигая цели») блок остаётся сплошным серым — выглядит как незалитая
заглушка.

**Убираем зависимость от фонового фото совсем**: простой заголовок
(`<h1 id="pageTitle">`) без баннера — подзаголовок (название
события/дистанция) уже реализован через существующий `updatePageTitle()`
(вставляет `<span class="page-title-event">` внутрь `#pageTitle`), новый
элемент не нужен. Селекторы Событие/Год переезжают в общий `.km-toolbar`
рядом с остальными фильтрами — обычные `.km-select`, без обёртки-панели
и без фонового изображения.

`.km-event-card`/`__overlay`/`__controls` в `analytics.css` **не
удаляются** — та же разметка используется в `start_list.html` (отдельный
будущий под-проект этой же программы редизайна, ещё не тронут).
`results.html` просто перестаёт использовать эту разметку/классы у себя
— CSS-правила остаются в файле для `start_list.html` до его собственного
цикла редизайна.

### 2. Фильтр «Пол» → pill-кнопки

Сейчас: `<select id="genderFilter">` с опциями, заполняемыми JS
(`populateGenderFilter()` в `analytics-results.js`) на основе реально
присутствующих в данных полов.

Новый вид: группа pill-кнопок (Все / Мужчины / Женщины — только те, что
реально есть в данных, как сейчас), розовый `--km-primary` для активной,
как у Siberman-пилюль формата/пола, но в цветах Красмарафона.

**Изменения в `analytics-results.js`**:
- `populateGenderFilter(runners)` — вместо `<option>` рендерит
  `<button class="km-pill" data-value="...">`, с `active`-классом на
  текущем выборе
- Новая `setGenderFilter(value)` — обновляет активный класс + вызывает
  `onGenderChange()` (та же функция, что сейчас вызывается по `onchange`
  у `<select>`)
- Везде, где код читает `document.getElementById('genderFilter').value`
  (минимум `applyFilters()`, `getActiveRankField()`) — заменить на чтение
  `data-value` активной пилюли через небольшой хелпер
  `getGenderFilterValue()`, чтобы не дублировать логику поиска
  `.km-pill.active` в нескольких местах

Возр. группа и Дистанция остаются `<select>` — опций много, pill-группа
была бы громоздкой (сам пользователь это подтвердил при выборе).

### 3. Таблица результатов

- `.km-th` — убрать `linear-gradient(to bottom, var(--km-primary), #1a1a1a)`,
  заменить на плоскую заливку `background: var(--km-primary)`. Hover
  (`.km-th--sort:hover`) — плоский чуть более тёмный оттенок вместо
  второго градиента
- Плотность: `.km-th` padding `12px 10px` → `9px 10px`; `.km-td` padding
  `11px 10px` → `9px 10px`. Шрифт таблицы (`13px`) не трогаем — уже
  читаемый
- `.km-rank-medal` (1-2-3, золото/серебро/бронза) — логика/цвета не
  меняются (уже корректны), только тень чуть плотнее
  (`0 2px 6px rgba(0,0,0,.2)` → `0 2px 8px rgba(0,0,0,.28)`) для более
  «премиального» вида

### Не в объёме этой спеки

- Сводные stat-карточки над таблицей (не выбраны пользователем)
- Любые изменения данных/API/бэкенда — только вёрстка/стили/клиентский JS
- Карточка над трекером и сам трекер (`tracker.html` карта) — исключены
  с самого начала всей программы редизайна
- Остальные страницы (`start_list.html`, `history.html` и т.д.) —
  отдельные будущие под-проекты

## Тестирование

- Unit-тесты на новую pill-логику фильтра пола (`node:vm`, тот же паттерн,
  что уже используется для JS-тестов Siberman в проекте, т.к. в проекте
  нет JS-тестового фреймворка) — `populateGenderFilter()` рендерит
  правильный набор пилюль по данным, `setGenderFilter()`/
  `getGenderFilterValue()` корректно переключают активную пилюлю и
  возвращают значение, `applyFilters()`/`getActiveRankField()` используют
  новое значение так же, как раньше использовали `select.value`
- Визуальная проверка в браузере (agent-browser) — десктоп и мобильная
  ширина, до отчёта о готовности: карточка события без фото рендерится
  чисто (не серым пустым блоком), pill-фильтр пола кликабелен и
  переключает результаты, таблица не переполняет мобильный экран,
  медальные бейджи видны на 1-2-3 местах
