# Демо «Повтор гонки» — часть 2: Siberman 2026

**Дата:** 02.11.2026
**Основание:** часть 1 (`2026-11-01-race-replay-demo-design.md`, опубликовано https://podbor16.github.io/race-tracker-demo/), решения в обсуждении 02.11.2026.
**Цель:** в той же витрине — live-результаты Siberman 2026 (06–08.08.2026, 3 дня, 62 записи участников: личники + эстафеты) так, будто гонка идёт сейчас; с карточками участников.

## 1. Решения

| Вопрос | Решение |
|---|---|
| Данные | Свежая копия прод-БД `siberman` в локальном MySQL (снята 02.11, только чтение) |
| Год | 2026 (якоря: старт 06.08 08:00, вело-2 07.08 08:00, бег 08.08 08:30) |
| Ночи | Ползунок по «времени гонки без ночей», кнопки «День 1 · плавание и вело», «День 2 · вело», «День 3 · бег», «Финиш» |
| Карточка участника | Собирается (статические страницы на каждого участника) |
| Брендинг | Шапка и логотип Siberman остаются (есть договорённость); сверху полоса «← Все демо · Siberman, 06–08.08.2026 — запись реальной гонки» |
| Как получить ответ на момент T | Песочница-БД `siberman_demo` + НЕИЗМЕНЁННЫЙ прод-путь записи/чтения |

## 2. Песочница и обезличивание

- `siberman_demo` (локальный MySQL :3308) пересоздаётся из локальной `siberman`. Копируются только таблицы результатов: `participants`, `checkpoints`, `checkpoint_times`, `transitions`, `stage_totals`, `overall_results`, `race_config`, `siberman_records`, `siberman_persons`, `siberman_person_links`. Таблицы жеребьёвки/заявок/контактов (`draw_*`, `siberman_applicants`, `siberman_entries*`, `siberman_person_reviews`, `siberman_person_audit`) не копируются.
- Обезличивание ВСЕХ лет (иначе в рекордах прошлых лет — реальные имена):
  - ФИО участников → сгенерированные (пол сохранён); один реальный человек (одинаковые фамилия+имя, при наличии — один `person_id`) → одно фейковое имя во всех годах;
  - `city`, `country` → NULL; `relay_team_name` → «Команда N»;
  - `siberman_records.holder_name` → то же сопоставление; `holder_team` → «Команда N» того же года/команды или NULL;
  - `siberman_persons`: ФИО → то же сопоставление, прочие персональные поля → NULL;
  - стартовые номера 2026 перемешиваются; у членов одной эстафеты номер общий.
- Стаж (`finish_count`) остаётся числом.
- Прод-побочный эффект `persons_service.sync_safe()` в процессе сборки подменяется no-op (как в тестах).
- Сборка работает только с локальной БД (`DB_HOST` 127.0.0.1/localhost, порт 3308), имя песочницы задаётся `SIBERMAN_DB_NAME=siberman_demo` в процессе сборки.

## 3. Проигрывание

- Итоговые данные 2026 (после обезличивания) читаются в память, затем результаты 2026 в песочнице очищаются (`checkpoint_times`, `transitions`, `stage_totals`, `overall_results` года; статусы участников → `active`).
- Абсолютный момент отметки:
  - `swim`, `bike_day1`: `race_start + cumulative_s`;
  - `bike_day2`: полночь 07.08 (Красноярск) + `bike_day2_handicap_s` участника + `cumulative_s`;
  - `run`: `run_start + cumulative_s`.
- Окна дней: [старт дня − 5 мин; последняя отметка дня + 5 мин]. Шаг 20 с (= интервал опроса страницы). На каждом шаге:
  1. upsert наступивших `checkpoint_times` (прод `db.upsert_checkpoint_time`);
  2. прод `service.recompute_totals_ranks_records(conn, 2026, participants, pid_cp_times)`;
  3. прод `db.get_results_for_year(conn, 2026)` + `db.get_all_records(conn)` → ответ в том же виде, что отдаёт `/api/siberman/results` (та же сериализация, что в `router.api_results`).
- Гандикап второго дня (`bike_day2_handicap_s`) виден только после окончания окна дня 1; DNF/DSQ/DNS — только после окончания окна дня 3.
- Даты `race_start`, `bike2_start`, `run_start` в ответе — ISO с `+07:00`.
- Запись: `{meta, initial, changes, days}`; `changes` — по шагам: изменившиеся элементы `individual` (ключ `bib`), `relay` (ключ `bib`) и изменившиеся общие поля (`records` и др.) целиком. `days`: `[{label, start_unix_ms, end_unix_ms}]`.
- Точность: в конце повтора `overall_s`, места (`rank_overall`, `overall_rank_g`, места этапов), суммы этапов и `records` совпадают с ответом прод-кода по копии 2026 у всех участников (кроме обезличенных полей).

## 4. Браузер и сайт

- Витрина: карточка «Siberman 2026 · Live-результаты · 3 дня · N участников».
- `siberman-2026/` — прод-шаблон `templates/siberman/results.html` без изменений; в `<head>` вставляется `demo-replay.js` (data-атрибуты: base, race, старт часов) — ДО скриптов страницы; полоса «← Все демо · подпись» вставляется в начало `<body>`. `og:url`/`og:image` указывают на демо.
- `demo-replay.js` обобщается «режимом»:
  - `tracker` (Жара) — как сейчас;
  - `poll` (Siberman) — перехват `fetch('/api/siberman/results…')` → ответ на текущий момент; EventSource и дистанция не используются.
- Виртуальные часы Siberman идут по «времени без ночей»: в конце окна дня часы прыгают ВПЕРЁД на начало следующего дня (назад — никогда); перемотка назад и новый круг — перезагрузкой с `?t=` (t — секунды «времени без ночей»). Повтор стартует с середины дня 1. Круг — после окна дня 3.
- Карточки: `siberman-2026/participant/<bib>/` — прод-шаблон `templates/siberman/participant.html` с тем же модулем; клики по ссылкам `/participant/<bib>…` перехватываются и открывают карточку с текущими `?t=&speed=`.
- Сборка: `python tools/demo/build.py zhara_21 zhara_5 siberman_2026`. Проверки ПДн/ссылок/`/api/` распространяются на Siberman (реальные ФИО, города, команды, рекордсмены всех лет).

## 5. Затрагиваемый код

- Прод-код Siberman (`src/siberman/`, шаблоны) — **не меняется**.
- `tools/demo/`: адаптер Siberman (песочница, обезличивание, проигрывание), обобщение `demo-replay.js`, `site.py`, `build.py`, `checks.py`, `races.py`.
- Жара после обобщения перепроверяется (unit + браузер).
