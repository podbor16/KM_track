# Редизайн race-analysis.html (вариант B: плашка-название + плоские карточки статистики) — дизайн

## Контекст

Третий под-проект программы «Редизайн всего сайта Красмарафона, кроме
карточки над трекером и самого трекера» (см. `текущие приоритеты.md` →
КРАСМАРАФОН → Подготовка к Жаре, п.1). Первые два под-проекта
(`results.html`, `start_list.html`) уже задеплоены.

`race-analysis.html` устроен принципиально иначе, чем предыдущие две
страницы: это не таблица с тулбаром/фильтрами, а сетка из 8 карточек-обложек
забегов (`static/images/events/logo1x1/*.png`), при клике на карточку
открывающая модальное окно с кросс-годовой статистикой события (Chart.js
график по годам, лучший результат, средние темпы) через
`/api/race-stats-db` (fallback `/api/race-stats`). Своя выделенная CSS
(`static/css/race-analysis.css`), `analytics.css` подключён в `<head>`, но
markup его классы не использует — общих стилей с results.html/start_list.html
у страницы нет.

Страница не входит в постоянную навигацию (`header.html`) — попасть на неё
можно только с `/history` (кнопка «Перейти к анализу забегов»), а `/history`
сейчас скрыт флагом `config/history_enabled.local` (временно выключен на
время подготовки к Жаре). Решение (подтверждено пользователем): редизайнить
сейчас, несмотря на текущую недостижимость из UI — страница должна быть
готова к моменту, когда история снова включится.

## Найденный баг (не связан с редизайном, чинится в любом случае)

`race-analysis.css` использует CSS custom properties, которых нет ни в
одном файле проекта: `--white`, `--shadow`, `--text-dark`, `--text-light`,
`--background`. `var(--undefined-name)` без fallback-значения резолвится не
в ошибку, а в `initial`-значение свойства (для неунаследуемых свойств) или
в унаследованное значение (для унаследуемых) — эффект разный в зависимости
от того, где именно переменная стоит:

- **`.race-modal-container { background-color: var(--white); }`** — реально
  видимый баг, воспроизведён вживую (agent-browser,
  `http://127.0.0.1:8129/race-analysis`, клик по любой карточке):
  `background-color` не наследуется, `initial` для неё — `transparent`.
  Модальное окно статистики рендерится без непрозрачного фона — текст
  виден прямо поверх карточек за ним, без читаемой панели.
- **`.race-card { box-shadow: var(--shadow); }`** и
  **`.back-button a { background-color: var(--white); box-shadow: var(--shadow); }`**
  — тоже реальный баг (`box-shadow`/`background-color` неунаследуемы,
  `initial` даёт `none`/`transparent`), но малозаметный на глаз: у карточек
  в состоянии покоя нет тени (но при hover появляется отдельная, явно
  захардкоженная — `0 12px 28px rgba(238,45,98,.2)`, она не затронута
  этим багом), а кнопка «Назад» с прозрачным фоном визуально почти не
  отличается от белого, потому что фон страницы (`--km-bg-page: #faf8fa`)
  и так почти белый.
- **`color: var(--text-dark)` / `var(--text-light)`** (заголовки, лейблы,
  значения статистики в модалке) — `color` наследуется, поэтому невалидный
  `var()` не даёт `initial`, а откатывается на унаследованное значение.
  Оно уже совпадает с `--km-text-body` (страница подключает
  `km-design-tokens.css`, где `body { color: var(--km-text-body); }`) —
  то есть здесь бага на глаз нет вообще, это просто хрупкая случайность
  (переопределение работает только потому, что unset-значение случайно
  совпало с нужным цветом через цепочку наследования).
- **`.race-analysis-container { background-color: var(--background); }`**
  — не баг, а мёртвый код: класс `race-analysis-container` не используется
  нигде в `race-analysis.html` (шаблон использует `<div class="container">`
  без префикса `race-analysis-`). Удаляется вместе с остальными правками
  как подтверждённо неиспользуемое правило.

Фикс: все реально используемые переменные заменяются на существующие
токены из `static/css/km-design-tokens.css` (даже там, где эффект
незаметен — ради консистентности и чтобы не зависеть от случайного
совпадения через наследование):

| Было | Станет |
|---|---|
| `var(--white)` | `var(--km-bg-card)` |
| `var(--shadow)` | `var(--km-shadow)` |
| `var(--text-dark)` | `var(--km-text-body)` |
| `var(--text-light)` | `var(--km-text-secondary)` |

`.race-analysis-container` (со своим `var(--background)`) — удаляется
целиком как мёртвый код, а не переносится на токен.

## Изменения

### 1. Карточки забегов — плашка-название вместо оверлея снизу

Сейчас: `.race-card-overlay` (тёмный градиент на всю карточку) +
`.race-card-content` (заголовок и описание, прижаты вниз, поверх и так
насыщенного фото-лого с собственным текстом внутри картинки — двойной
текст, трудно читать).

Новая разметка карточки (пример для одной, остальные 7 аналогично):
```html
<div class="race-card" data-race-id="night_run" data-race-name="Ночной забег">
    <div class="race-card-image"></div>
    <div class="race-card-badge">Ночной забег</div>
</div>
```
Удаляется: `.race-card-overlay`, `.race-card-content`,
`.race-card-title`, `.race-card-description` (и их разметка во всех 8
карточках — `data-race-name` остаётся, JS его уже читает через
`card.dataset.raceName`, менять `race-analysis.js` не нужно).

Новый CSS-класс `.race-card-badge`: компактная белая плашка-пилюля в
левом верхнем углу карточки (`position: absolute; top/left: 12px`, белый
фон `var(--km-bg-card)`, `border-radius: var(--km-radius-btn)`, тёмный
текст `var(--km-text-body)`, `padding: 6px 14px`, `font-size: 13px`,
`font-weight: 600`, `box-shadow: var(--km-shadow)`), не перекрывает
основную часть фото. Описание забега на карточке больше не показывается —
оно остаётся в модалке при клике (`getRaceDescription()` в
`race-analysis.js`, не трогаем).

`.race-card-image` остаётся как есть (`background-size: cover`,
`object-fit: cover`, hover-масштабирование `scale(1.04)`) — фото-лого
показывается полностью, без второго слоя текста.

Тени карточек (`box-shadow: var(--shadow)` на `.race-card`, hover-тень
`0 12px 28px rgba(238,45,98,.2)`) переезжают на `var(--km-shadow)` /
`var(--km-shadow-hover)` соответственно.

Мобильная адаптация: текущее правило `@media (max-width: 768px) { .race-card-content { display: none; } }`
удаляется вместе с `.race-card-content` — на мобильном плашка-название
видна всегда (она компактная и не мешает), как и на десктопе.

### 2. Модальное окно статистики — плоские карточки вместо цветных градиентов

Затрагивает три блока в `.race-modal-body` (генерируются в
`displayRaceModal()`, `race-analysis.js`, markup не меняем — меняем
только CSS-классы, которые уже проставлены):

- **`.stat-item`** (грид «Всего участников»/«Финишировали»/«Мужчин»/«Женщин»):
  убираются цветные `border-left` (4px, разные цвета по `:nth-child`) и
  серый фон `#f8f9fa`. Новый стиль: `background: var(--km-bg-card)`,
  `border: 1px solid var(--km-border-light)`,
  `border-radius: var(--km-radius-card)`, без цветного акцента слева.
  Число (`.stat-value`) остаётся крупным и жирным, цвет `var(--km-text-body)`.
- **`.best-result`**: убирается градиентный фон
  (`linear-gradient(135deg, #fff5f8, #fffbfc)`) и цветной `border-left`.
  Новый стиль: та же плоская карточка, что у `.stat-item`
  (`var(--km-bg-card)` + `var(--km-border-light)` + `var(--km-radius-card)`).
  Метрики времени/темпа (`.metric-value`) остаются акцентными —
  `color: var(--km-primary)`.
- **`.pace-item`** (грид «Общий темп»/«Мужчины»/«Женщины»): убираются три
  разных цветных фона (`#f0f8ff`/`#f8f5ff`/`#fff5f8`) и цветной
  `border-top`. Тот же единый плоский стиль, что у `.stat-item`.

**`.section-title`** (заголовки «Статистика», «Лучший результат», «Средний
темп участников»): убирается цветной нижний бордер
(`border-bottom: 2px solid #f0f0f0`) и `color: var(--km-primary)` на всём
заголовке. Новый стиль: обычный uppercase-лейбл —
`font-size: 13px`, `text-transform: uppercase`, `letter-spacing: .5px`,
`color: var(--km-text-body)`, без цветного подчёркивания. Цветовой акцент
остаётся только на цифрах/значениях, не на заголовках секций.

`.distance-block-title` (используется только когда у события несколько
дистанций) — та же переработка: убрать цветной `border-bottom`, оставить
uppercase-лейбл.

### 3. Chart.js — без изменений

Датасеты графика («Всего участников»/«Финишировали»/«Мужчины»/«Женщины»)
сохраняют текущие 4 разных цвета (`#EE2D62`/`#059C43`/`#562872`/`#00BFDF`)
— нужны визуально различимые линии, однотонная брендовая палитра здесь не
подходит. `displayRaceChart()` в `race-analysis.js` не трогаем.

### 4. Токены (см. таблицу бага выше)

Помимо замены отсутствующих переменных, `--shadow` в существующих
составных объявлениях (`box-shadow: var(--shadow)` на `.race-card`,
`.back-button a`) заменяется на `var(--km-shadow)` — уже готовое составное
значение (`0 2px 8px rgba(0,0,0,0.1)`), а не голый цвет, поэтому синтаксис
объявления не меняется, меняется только имя переменной.

### 5. Заголовок страницы и кнопка «Назад» — только токены, без структурных изменений

`.race-analysis-header h1` получает `id="pageTitle"` для консистентности
разметки с results.html/start_list.html (`<h1 id="pageTitle">`) — чисто
атрибут, визуально ничего не меняется, свой блок `.race-analysis-header`
сохраняется как есть (центрированный заголовок + подзаголовок — общий
паттерн `.km-page`/`.km-toolbar` сюда не переносим, эта страница не
табличная).

Кнопка «Вернуться к поиску» остаётся функционально как есть — ведёт на
`/history`, поведение и цель ссылки не меняются (подтверждено
пользователем: когда история снова включится, всё уже будет связано
правильно). Меняются только цвета/тени: `border-color`/`color` с
хардкода `#EE2D62` на `var(--km-primary)`, `box-shadow` с
`var(--shadow)` на `var(--km-shadow)`.

## Не в объёме этой спеки

- API (`/api/race-stats-db`, `/api/race-stats`) и логика загрузки данных
  (`loadRaceStats()`, fallback-цепочка) — не трогаем
- `race-analysis.js` — меняются только используемые CSS-классы в разметке
  карточек (см. №1), сам JS-файл не редактируется
- Добавление страницы `/race-analysis` в постоянную навигацию
  (`header.html`) — подтверждено пользователем: страница остаётся
  достижимой только через `/history`, как сейчас
- Карточка над трекером и сам трекер — исключены с самого начала всей
  программы редизайна
- Остальные страницы (`history.html`, `athlete-profile.html`,
  `business-analytics.html`, `admin.html`) — отдельные будущие
  под-проекты

## Тестирование

- Визуальная проверка в браузере (agent-browser), десктоп и мобильная
  ширина — карточки: плашка-название видна и не обрезана, фото-лого без
  второго текстового слоя, hover-эффект работает; модалка: белый
  непрозрачный фон с тенью (баг с прозрачностью исчез), плоские карточки
  статистики без цветных градиентов, график Chart.js рендерится с
  прежними 4 цветами линий
- JS-тестов не требуется — `race-analysis.js` не редактируется, изменения
  чисто в HTML-разметке (замена классов на карточках) и CSS
- Полный прогон существующего тестового набора (`pytest tests/unit/
  tests/integration/`) — регрессионная проверка, страница не покрыта
  собственными тестами до и после этой спеки
