# Скрыть историю участий на время Жары — дизайн

## Контекст и проблема

БД Красмарафона содержит результаты гонок практически только с 2024 года
(загружены через загрузчики результатов/Copernico). Данные 2013–2023
отсутствуют почти полностью. Раздел «История участия» показывает
кросс-годовую историю конкретного спортсмена — для ветерана, бегавшего
каждый год с 2015-го, страница сейчас покажет «начал бегать в 2024»,
что хуже, чем не показывать ничего.

Перед гонкой «Жара» (22–23.08.2026) полную историческую базу залить не
успеваем. Решение: временно полностью скрыть раздел истории — и нав-пункт,
и сами страницы, и API — до тех пор, пока историческая база не будет
загружена (отдельная, более поздняя по приоритету задача бэклога —
см. «Импорт исторических данных 2013–2023 из Excel/PDF в БД», не входит
в рамки этой спеки).

## Поверхность (что скрываем)

Найдено при исследовании кода:

- Нав-пункт «ИСТОРИЯ» в `templates/krasmarafon/header.html` (виден на
  всех страницах сайта)
- Страница `/history` (`templates/krasmarafon/history.html`) — две опции:
  поиск спортсмена (→ `/athlete-profile`) и «Анализ по забегам»
  (→ `/race-analysis`)
- Страница `/athlete-profile` (`templates/krasmarafon/athlete-profile.html`)
  — собственно кросс-годовая история, это и есть проблемная часть
- API: `GET /api/search-athletes`, `GET /api/athlete/{surname}/{name}`

**НЕ трогаем** `/race-analysis` — это аналитика по одному уже загруженному
событию/году (полные корректные данные для загруженных гонок), не
кросс-годовая личная история. Пробел 2013–2023 её не касается.

Больше нигде в интерфейсе (результаты, трекер) прошлые старты/финиши
участника не отображаются — проверено, других мест для правки нет.

## Архитектура: переключатель через файл вне git

По аналогии с уже существующим `config/active_event.local`
(`src/config/event_loader.py::get_active_event_override()` /
`set_active_event_override()`) — тот же паттерн: булев флаг, который
переживает деплой (`git checkout` не затирает переключение на проде), без
миграции БД.

**Рассмотренные альтернативы:**
- Новая таблица БД (settings key-value) — более «правильно» для будущего
  множества флагов, но лишняя миграция + DB round-trip на каждый рендер
  страницы ради одного булева значения. Overkill для текущей задачи.
- Хардкод в коде + git revert позже — отклонено пользователем явно:
  переключать должен он сам через `/admin`, без обращения к агенту.

### Хранение

`config/history_enabled.local` (не в git, аналогично `active_event.local`):
- Содержимое `"false"` → история выключена
- Файл отсутствует → включено (текущее поведение, дефолт)

### Чтение

`get_history_enabled() -> bool` в `src/config/event_loader.py`, рядом с
`get_active_event_override()`. Читает файл при каждом вызове (без TTL-кеша
— задача переключается вручную через admin, не требует горячей
перезагрузки каждые N секунд, а любая задержка отражения переключения
недопустима для этого конкретного флага).

`set_history_enabled(enabled: bool) -> None` — пишет/удаляет файл.

### Доступность в шаблонах

Регистрируется как Jinja global сразу после создания `Jinja2Templates` в
`src/krasmarafon/routers/pages.py:50` (там же, где определены роуты
`/history`/`/athlete-profile`, и куда `header.html` подключается через
`{% include %}`): `templates.env.globals['history_enabled'] =
get_history_enabled`. Так флаг доступен в любом шаблоне без правки
контекста каждого роута.

В `header.html`:
```jinja
{% if history_enabled() %}
<a href="/history" class="navbar-link">ИСТОРИЯ</a>
{% endif %}
```

### Блокировка прямого доступа

Не только прячем ссылку — сами роуты тоже должны быть недоступны по
прямому URL:

- `GET /history`, `GET /athlete-profile` (`src/krasmarafon/routers/pages.py`)
  — если `not get_history_enabled()`, редирект на `/` (302)
- `GET /api/search-athletes`, `GET /api/athlete/{surname}/{name}`
  (`src/krasmarafon/routers/api.py`) — если `not get_history_enabled()`,
  `404` (данных «как будто нет», не «доступ запрещён» — не подсказываем,
  что раздел временно спрятан, а не удалён)

### Переключатель в `/admin`

В `templates/krasmarafon/admin.html` — чекбокс/кнопка, тот же визуальный
паттерн, что уже есть у Siberman-поллеров («Включить»/«Выключить»).

Новый эндпоинт `POST /api/admin/history-toggle` в
`src/krasmarafon/routers/admin.py` (защищён `api_require_auth`, как и
остальные admin-эндпоинты) — принимает `enabled: bool`, вызывает
`set_history_enabled()`.

## Тестирование

- Unit: `get_history_enabled()`/`set_history_enabled()` — файл
  отсутствует → `True`; файл с `"false"` → `False`; round-trip через
  `set_history_enabled(False)` → `get_history_enabled() == False`
- Integration: при выключенном флаге — `GET /history` и
  `GET /athlete-profile` отдают 302, `GET /api/search-athletes` и
  `GET /api/athlete/{surname}/{name}` отдают 404; при включённом —
  поведение не меняется относительно текущего
- Ручная проверка: нав-пункт «ИСТОРИЯ» пропадает с любой страницы сайта
  при выключенном флаге; `/admin` переключатель меняет состояние без
  редеплоя

## Вне рамок этой задачи

  используемый импорт-процесс)
