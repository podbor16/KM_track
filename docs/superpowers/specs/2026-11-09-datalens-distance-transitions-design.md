# DataLens: «Переходы дистанций» — дизайн

**Дата:** 2026-11-09 · **Статус:** согласован с пользователем

## Зачем

Чарт «Переходы дистанций» (вкладка «Мероприятия» дашборда «Красмарафон — Аналитика») сейчас некорректен:
дистанции сравниваются как строки ('21.1 км' < '5 км'), забеги не сопоставляются (Снежная 2 км → Жара 21,1 км —
«переход»), берутся все пары «участие → любое более позднее участие», селекторы вкладки его не фильтруют,
на вкладке висит ошибочный алиас `event_year ↔ from_distance`.

Новый набор виджетов отвечает на три вопроса организатора:
1. **Растут ли бегуны** — переходы между дистанциями внутри одного забега от участия к участию.
2. **Куда уходят люди между забегами** — с какого забега/дистанции пришли на выбранный забег.
3. **Что выбирают вернувшиеся** — для выбранного забега и года: прошлая дистанция → текущая, и сколько впервые.

## Правила

- **Единица счёта** — участие человека в забеге в году: (`client_id`, `event_name`, `event_year`).
  Несколько заявок одного человека на забег в один год (две дистанции) — одна строка, дистанция = **самая длинная**.
- **Возвраты не считаются** (`leads.refund > 0` исключены).
- **Дистанция** сравнивается **числом** из `events.event_distance` (0.5 / 1 / 2 / 5 / 7 / 10 / 21.1).
- **Пара «тот же забег»** — предыдущее участие человека в этом же `event_name` (предыдущий год с участием).
  Направление: `Выросли` (сейчас длиннее), `Сократили`, `Та же дистанция`, `Впервые на забеге` (нет предыдущего).
  **Детский забег** — поля пары «тот же забег» пустые: дистанцию определяет возраст, а не выбор.
- **Пара «любой забег»** — предыдущее участие человека в любом забеге по дате забега
  (`events.event_date`; если пусто — середина года `event_year`), при равенстве — по году и названию.
  Детский забег здесь учитывается (переход «Детский → взрослый забег» интересен).
- **Селекторы вкладки** (Год / Мероприятие / Дистанция из `km_leads`) фильтруют сторону **«сейчас»**.

## Архитектура

Пары считаются оконными функциями `LAG` по всем заявкам — ~3 с на запрос (замер на проде 2026-11-09).
Считать это на каждый запрос виджета нельзя, поэтому результат **материализуется в таблицу MySQL**,
которую раз в час пересчитывает **событие MySQL** (на проде `event_scheduler` включён). Код приложения не меняется.

### Таблица `krasmarafon.km_transitions`

| Колонка | Тип | Смысл |
|---|---|---|
| `client_id` | INT | человек |
| `event_name` | VARCHAR | забег «сейчас» |
| `event_year` | INT | год «сейчас» |
| `event_distance` | VARCHAR | дистанция «сейчас» строкой, как в `leads` («7 км») — для селектора |
| `dist` | DECIMAL(5,1) | дистанция «сейчас» числом |
| `same_prev_year`, `same_prev_dist` | INT, DECIMAL | предыдущее участие в этом же забеге |
| `same_direction` | VARCHAR | Выросли / Сократили / Та же дистанция / Впервые на забеге (NULL для Детского) |
| `any_prev_event`, `any_prev_year`, `any_prev_dist` | VARCHAR, INT, DECIMAL | предыдущее участие в любом забеге |
| `refreshed_at` | DATETIME | момент пересчёта |

Ключ — (`client_id`, `event_name`, `event_year`); индекс по (`event_name`, `event_year`).

### Пересчёт — событие `ev_refresh_km_transitions`

`EVERY 1 HOUR`, `DEFINER = root@localhost` (как триггеры прода). Собирает `km_transitions_new` тем же SQL,
затем атомарно `RENAME TABLE km_transitions TO km_transitions_old, km_transitions_new TO km_transitions`
и `DROP km_transitions_old` — DataLens никогда не видит полузаполненную таблицу.
Права: `datalens_ro` уже имеет `SELECT ON krasmarafon.*`.

Файл: `migrations/km_transitions.sql` (таблица + первичное заполнение + событие), применяется на проде от root.

### DataLens

- Датасет **`km_transitions`** (источник — таблица, подключение «Красмарафон. БД с пользователями»).
- Виджеты на вкладке «Мероприятия» (вместо «Переходы дистанций»):
  1. **Матрица «было → стало»** (сводная таблица): строки `same_prev_dist`, столбцы `dist`, значение — число людей;
     только строки с парой «тот же забег».
  2. **Индикаторы** «Выросли», «Сократили», «Та же дистанция» — люди и % от повторных участников
     (`same_prev_dist IS NOT NULL`).
  3. **Индикатор** «Впервые на забеге».
  4. **Таблица потоков** «предыдущий забег + дистанция → дистанция сейчас», люди, по убыванию;
     только `any_prev_event <> event_name`.
- Вкладка «Мероприятия»: алиасы селекторов `km_leads.event_year / event_name / event_distance` ↔
  `km_transitions.event_year / event_name / event_distance`; удалить алиас `event_year ↔ from_distance`
  и `ignore`-связи селектора года.
- Старый чарт «Переходы дистанций» и датасет `km_distance_transitions` удаляются **после** проверки новых
  (бэкап — `Claude outputs/datalens_backup_2026-11-09/`).

## Проверка

- Таблица: число строк и выборочные цифры совпадают с прямым SQL; контроль на Снежной семёрке 2026
  (по заявкам: та же дистанция 188, выросли 9, сократили 6, впервые 230 — по людям цифры могут быть чуть меньше).
- Событие: `SHOW EVENTS`, `refreshed_at` обновляется; время пересчёта ~3 с.
- DataLens: все виджеты дашборда строятся (прогон через embed API, как выгрузка в Excel), селекторы фильтруют
  новые виджеты; `Max_execution_time_exceeded` не растёт.

## Откат

`DROP EVENT ev_refresh_km_transitions; DROP TABLE km_transitions;` — вернуть датасет `km_distance_transitions`
и чарт из бэкапа (или не удалять их до приёмки).

## Вне рамок

- Пересчёт сразу после импорта Tilda (пока раз в час).
- Динамика переходов по годам (столбчатая «выросли/сократили» по годам) — при необходимости позже.
