# Siberman: приём и проверка заявок (часть A) — дизайн

Дата: 2026-10-27. Решения пользователя — в разговоре 2026-10-27 (ответы на вопросы ниже помечены «решение»).

## Цель

Заявки на Siberman (с 2029) приходят из формы Тильды автоматически. Директор гонки в одной вкладке админки
смотрит все заявки с контактами, ставит статус и комментарий, выгружает Excel. На публичной странице (iframe
в Тильде) — список всех заявок со статусами.

Вне этой спеки (часть B + C, задача в Obsidian `inbox/2026-10-27-siberman-draw-chances-automation.md`):
расчёт шансов, связь со жеребьёвкой, шансы между годами. Уведомления о новых заявках — не делаем.

## Решения

| Вопрос | Решение |
|---|---|
| Как заявки попадают к нам | вебхук Тильды (вторым приёмником формы, лист Tilda CRM остаётся) + разовая загрузка CSV для уже пришедших. MCP Тильды не подходит: он для ИИ-сессии, а не для сервера, и CRM пока не поддерживает |
| Повторная заявка человека | каждая заявка — отдельная строка со своим статусом |
| Статусы | ⌛️ на изучении (по умолчанию) · ✅ допущена к жеребьёвке · ❌ не соответствует требованиям · 🚫 отказался от участия в жеребьёвке (допущен, сам отказался до жеребьёвки — шансы сохраняются; нужен частям B/C) |
| 🚫 публично | да, с легендой |
| Комментарий | да, только в админке и Excel; плюс журнал смены статусов |

## Данные — миграция 018

`siberman_entries` — одна строка на заявку (`tranid` Тильды):

| Поле | Тип | Откуда (поле формы Тильды) |
|---|---|---|
| id | INT AI PK | |
| race_year | SMALLINT | из адреса вебхука / выбранного года при загрузке CSV |
| tranid | VARCHAR(64) UNIQUE | `tranid` |
| formid | VARCHAR(64) | `formid` |
| submitted_at | DATETIME | время приёма вебхука (Красноярск) / `Date` из CSV |
| format | ENUM('individual','relay') | `format` («Индивидуальное участие» / «Эстафетная команда»; иное — ошибка, заявка в failed/) |
| surname, name | VARCHAR(100) | `surname`, `Name` |
| gender | ENUM('M','F') NULL | `sex` (у эстафеты NULL) |
| birthdate | DATE NULL | `birthday` (разбор как `persons.applicants.parse_birthdate`) |
| city | VARCHAR(150) | `city` |
| email, phone | VARCHAR(255) / VARCHAR(64) | `Email`, `Phone` |
| team_name | VARCHAR(150) | `team_name` |
| relay_swim / relay_bike / relay_run | VARCHAR(255) | `surname_<этап>` + `name_<этап>` |
| wildcard_reason, results_text | TEXT | `wildcard_reason`, `Расскажите_о_ваших_результатах` |
| result_url | VARCHAR(500) | `result_url` |
| raw | JSON | всё тело от Тильды (поля, которых нет в колонках: `tattoo`, `222_starts`, `24h_starts`, `siberman_draw` … — для части B) |
| status | ENUM('review','admitted','rejected','withdrawn') DEFAULT 'review' | |
| comment | TEXT | директор |
| status_updated_at, status_by | DATETIME / VARCHAR(64) | |

`siberman_entries_audit` — id, entry_id, action ('status' / 'comment'), old_value, new_value, admin_user, created_at.

Повторная доставка того же `tranid` (вебхук повторно, CSV поверх вебхука) обновляет поля заявки из формы,
**не трогая** status/comment. Индекс (race_year, submitted_at).

## Модуль `src/siberman/entries/`

- `parser.py` — тело Тильды (dict) → поля заявки; чистая функция, общая для вебхука и CSV (CSV-строка Тильды
  имеет те же имена полей).
- `db.py` — upsert по tranid, список года, смена статуса/комментария с аудитом, журнал заявки.
- `service.py` — приём (вебхук/CSV), состояние админки, публичный список, Excel.
- `router.py` — эндпоинты ниже.

## Приём

- `POST /webhook/siberman/{token}/{year}`; `token` = новый `SIBERMAN_WEBHOOK_SECRET` (.env), иначе 403; год —
  2020–2100, иначе 404.
- Тестовый запрос Тильды при подключении (`test=test`) → 200 «ok», ничего не создаёт.
- Надёжность — как у вебхука Красмарафона: тело сначала в спул на диск (отдельный каталог
  `var/webhook_spool/siberman/`), потом в БД; ошибка БД — файл остаётся, лидер-воркер повторяет его каждые
  5 минут (тот же `_webhook_spool_replayer` в `app.py`, обобщить `spool_save`/`replay_spool` на каталог и
  обработчик). Тильда всегда получает 200 после записи в спул. Тело, не превращающееся в заявку (нет ФИ /
  непонятный формат), — в `failed/` и ntfy, как у Красмарафона.
- `POST /api/siberman/admin/entries/{year}/import` (CSV Тильды, «;», UTF-8/cp1251) — разовая загрузка; отчёт:
  строк, новых, уже были, ошибок.

## Админка — таб «Заявки» в `/admin/draw?year=…`

- Выбор года вверху таба (годы, по которым есть заявки, + текущий из адреса); смена года перезагружает страницу
  с `?year=`.
- Счётчики: всего, ⌛️, ✅, ❌, 🚫.
- Поиск по фамилии и имени (без регистра, ё = е, в любом порядке слов); фильтр по статусу.
- Таблица в порядке прихода (submitted_at, id): № по приходу, дата и время, ФИ, формат, пол, город, e-mail,
  телефон, статус (выпадающий список — сохраняется сразу), комментарий (сохраняется при уходе с поля).
- Клик по строке — карточка: ДР, команда и состав эстафеты, тексты, ссылка на результаты, журнал статусов.
- «Скачать Excel» — все колонки таблицы + ДР, команда, состав, тексты, комментарий; шапка закреплена, фильтры
  (как Excel для счетов).
- «Загрузить CSV из Тильды».
- API (все — `api_require_auth`): `GET /api/siberman/admin/entries/{year}`, `POST …/{entry_id}/status`
  (`status`), `POST …/{entry_id}/comment`, `GET …/{entry_id}` (карточка + журнал), `GET …/export.xlsx`,
  `POST …/import`.

## Публичная страница — `/entries/{year}` (домен siberman, для iframe)

- Сверху: «Заявок: N, допущено: M»; легенда статусов; поиск по фамилии и имени.
- Таблица: № (по порядку в выдаче), Фамилия Имя, Формат участия, Статус (эмодзи). Сортировка по алфавиту
  (фамилия, имя; ё = е).
- Данные — `GET /api/siberman/entries/{year}`: только `fio`, `format`, `status`; ни контактов, ни ДР, ни
  комментариев. Кэш в памяти воркера на несколько секунд; страница обновляется сама раз в минуту.
- Стиль — как у остальных iframe-блоков Siberman (hall), тёмная/светлая тема, телефон.

## Ошибки

- БД недоступна при чтении — 503 и сообщение (страница повторит), при записи статуса — сообщение в админке,
  статус в строке откатывается.
- Неизвестный статус / чужой год / нет заявки — 404/409 с текстом.

## Проверка

- Unit: parser (поля, формат, пол, ДР, эстафета, мусор), поиск (ё, порядок слов).
- Integration (локальная БД): вебхук — неверный секрет 403, тест-пинг, приём, повторная доставка не меняет
  статус, восстановление из спула; CSV поверх вебхука без дублей; статусы и журнал; публичный API без
  контактов; Excel; авторизация админ-эндпоинтов.
- Браузер: таб «Заявки» на компьютере (смена статуса, поиск, карточка, Excel), публичная страница на телефоне.
- Прод: бэкап → миграция 018 → `SIBERMAN_WEBHOOK_SECRET` в .env → деплой → тестовый POST. Подключение вебхука в
  форме Тильды делает пользователь (вход в аккаунт Тильды); адрес даём из админки (кнопка «Скопировать адрес
  вебхука» в табе).
