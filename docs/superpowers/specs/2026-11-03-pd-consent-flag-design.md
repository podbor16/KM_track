# Флаг «не согласен на публикацию ПД» — дизайн

Дата: 2026-11-03. Статус: согласован с пользователем (brainstorming), ждёт ревью спецификации.
Срок: Снежная семёрка 2026 (06.12). Часть 1 из 5 задачи «согласие на ПД + вход спортсмена»
(Obsidian: `inbox/2026-11-02-krasmarafon-pd-consent`, `inbox/2026-11-03-krasmarafon-athlete-auth`).

## Проблема

С Снежной семёрки 2026 участник подписывает согласие на публикацию ПД — **на бумаге при получении
номера**, отдельное на каждое событие каждого года. Без согласия публиковать его ПД нельзя, даже ФИ.
Сейчас в системе нет ни места для отметки, ни скрытия.

## Требования

- Отметка «не согласен» — на заявку конкретного события; ставит оператор вручную в админке.
- По умолчанию публикуем: скрываем только явно отмеченных.
- У отмеченного во всех публичных выдачах: вместо ФИ — **«Спортсмен»**, без даты рождения, без ссылки
  на карточку. Остаются стартовый номер, пол, категория, время, места. (Город и клуб в публичных
  выдачах результатов не выводятся вообще.)
- Скрытие на сервере — настоящие ФИ не попадают ни в ответ API, ни в кеши.
- Закрытые входом страницы (стартовый список, `/admin`) и выгрузка для Copernico — с настоящими ФИ
  (Copernico результаты не публикует — ответ пользователя 2026-11-03).

Вне рамок (решения пользователя 2026-11-03): скрытие ФИ у всех участников событий 2021–2026 (позже,
на этом же механизме); правило 30 лет (первые события перешагнут срок в 2043); отзыв согласия
задним числом; вход и личная история (части 2–5).

## Данные

Миграция `migrations/lead_pd_refused.sql` (идемпотентно, по образцу `lead_tilda_account.sql`):

```sql
ALTER TABLE leads ADD COLUMN pd_refused TINYINT(1) NOT NULL DEFAULT 0;
```

Флаг в `results` не копируется. Результат ↔ заявка — по `event_id + start_number` (так же их связывает
триггер `trg_results_before_insert`, индекс `idx_leads_event_bib` есть). Запросы результатов
подтягивают флаг подзапросом:

```sql
EXISTS (SELECT 1 FROM leads l WHERE l.event_id = r.event_id AND l.start_number = r.start_number
        AND l.pd_refused = 1) AS pd_refused
```

Поэтому отметка, поставленная после загрузки результатов, действует сразу (после истечения кешей).
Результат без заявки (номер не совпал) — не скрыт; это осознанный риск, оператор ставит флаг на заявку
с правильным номером.

## Админка

По образцу «Элита» (`/api/admin/leads/{id}/elite`, `set_lead_elite`):

- `POST /api/admin/leads/{lead_id}/pd-refused?refused=1|0` → `set_lead_pd_refused()` в `db_results.py`.
- Запись в журнал `dq_actions` (кто, когда, заявка, новое значение) — через `_log_action`.
- После записи — `invalidate_start_list_cache()` и сброс кешей результатов этого воркера; остальные
  воркеры подхватят по TTL (5–30 с).
- `LeadAdminItem` — поле `pd_refused`; в строке заявки — кнопка «Не согласен на ПД» / «Снять» и бейдж.
- Стартовый список (под входом) — бейдж в строке, ФИ настоящие.

## Маскировка

Новый модуль `src/krasmarafon/services/public_pd.py`:

```python
PLACEHOLDER = "Спортсмен"
def mask_runner(row: dict) -> dict  # копия строки: ФИ → PLACEHOLDER, full_name → PLACEHOLDER,
                                    # birthday/birth_year → None, client_id → None; если pd_refused
```

Точки вызова (найдены разведкой 2026-11-03):

| # | Выдача | Где маскировать |

| 7 | `/api/race-stats` (fallback из `data/race_data.json`) | маскировать по номеру: набор номеров с отказом для события из `leads` |

Важно для п. 1: строки `get_race_results_by_event_id` используются также для подбора темпа по
«ФИ+ДР» (`load_hist_data`, `get_prev_year_results`) — поэтому маскировать в `assemble`, а не в
функции БД.

## Ошибки и граничные случаи

- Флаг на заявке без номера — действует, как только номер присвоен (подзапрос по номеру).
- Две заявки с одним номером на событии (дубли) — достаточно флага на любой.
- Снятие флага — ФИ возвращаются после истечения кешей.

## Тесты

- Unit: `mask_runner` (с флагом / без; исходная строка не меняется).
- Unit/интеграция (локальная БД): тестовая заявка с флагом + результат с тем же номером → в каждой
  выдаче из таблицы (1–7) нет фамилии и имени, есть номер и время; без флага — ФИ на месте.
- Эндпоинт админки: ставит/снимает флаг, пишет в журнал, требует вход.
- Браузерная проверка `/results`, трекера и диплома на локальной БД.
