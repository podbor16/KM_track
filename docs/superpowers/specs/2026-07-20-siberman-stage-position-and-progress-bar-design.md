## Контекст

Два пункта из бэклога Siberman (п.11/п.12 сырой спеки `2026-07-19-siberman-results-v3-tasks`, отложены пользователем как необязательные на прошлой итерации):

- **П.11** — график места **по этапам** (сейчас есть только «Позиция» — абсолютное место по всей гонке 0→515 км).
- **П.12** — бегунок прохождения КТ вида «N/M км», зависит от п.11.

Оба реализуются без нового backend — все нужные данные и хелперы (`computeCheckpointRanks`, `currentStage`, `lastReached`, `CHECKPOINT_DIST_KM`, `STAGE_KM_OFFSET`, `kmToVirtualX`) уже есть в `siberman-common.js` / `results.html`.

## Часть 1 — Место по этапам (график «Позиция»)

### Что строим

Встраиваем переключатель этапа в СУЩЕСТВУЮЩИЙ график «Позиция» на `/siberman/results` (вкладка «График» → подтаб «Позиция») — не отдельный подтаб. Переключатель — та же группа кнопок, что уже используется у «Темп/скорость» (`Плавание / Вело День 1 / Вело День 2 / Бег`), плюс дополнительная кнопка **«Вся гонка»** первой в списке (текущее поведение по умолчанию).

### Поведение

- **«Вся гонка»** (по умолчанию, как сейчас): X — виртуальные проценты 0–100 (пропорции 20/50/30), Y — абсолютное место в общем зачёте на каждой КТ (`computeGlobalCheckpointRanks`). Без изменений относительно текущей реализации.
- **Выбран конкретный этап**: X — реальный километраж ВНУТРИ этапа (0 → длина этапа: 10/145/276/84), Y — **место внутри этого этапа** (`computeCheckpointRanks(rows, stage, maxSeq)` — уже существующая функция, сравнивает участников только по времени НА этом этапе, не по совокупному времени гонки). Границы дней (Вело1/Вело2) в этом режиме не показываются — это уже одна дистанция целиком.
- Y-ось в обоих режимах — те же правила из текущей реализации: `reverse` не нужен (меньше место — выше), целые тики `afterBuildTicks` (1..maxRank данного набора участников на этом этапе), асимметричный запас сверху под подпись.
- Точки на графике — по реальным КТ этапа (как сейчас), без экстраполяции до x=0 в per-stage режиме (у этапа есть настоящая КТ около начала, экстраполяция была нужна только для глобального 0 км старта гонки).
- Единая плашка hover (`formatPoint`) — переиспользуется, текст: `{km внутри этапа} км: место {N}`.
- Мультивыбор для сравнения — работает как сейчас, независимо от режима.

### Изменения в коде

`templates/siberman/results.html`, зона `renderPositionChart()`:
- Новое состояние `_positionStage` (`null` = «Вся гонка», либо один из `STAGE_ORDER`), по аналогии с `_paceStage`.
- Кнопки переключения — переиспользовать разметку/обработчики группы `#paceStageGroup`, продублировать с новым id для позиции.
- `buildPositionDatasets()` — ветвление: если `_positionStage === null`, текущая логика (все этапы, `STAGE_KM_OFFSET`, `computeGlobalCheckpointRanks`); если конкретный этап — цикл только по этому этапу, X = реальный км (без `kmToVirtualX`/`withVirtualX` — ось X в этом режиме линейная в реальных км, не виртуальная), Y = `computeCheckpointRanks`.
- Ось X (`scales.x`) — `max` меняется по режиму: 100 (виртуальный) vs `CHECKPOINT_DIST_KM[stage][STAGE_MAX_SEQ[stage]]` (реальный км этапа).
- Подписи границ этапов (`stageBoundaryPlugin`) — не рисуются в per-stage режиме (нет смысла, весь график — один этап).

## Часть 2 — Бегунок прохождения КТ

### Расположение

`participant.html` — сразу под блоком ФИО/названия команды, **перед** индикаторами (Итого/Место/Отставание). Для личников и эстафетных команд — одинаковый компонент.

### Визуал (вариант B из мокапа, согласован с пользователем)

Горизонтальная полоса 0→515 км:
- 3 цветных сегмента по виртуальным долям — переиспользуем `POSITION_X_SEGMENTS`/`kmToVirtualX()` из results.html (константу и функцию нужно вынести в `siberman-common.js`, т.к. сейчас они объявлены только в `results.html`, а нужны и в `participant.html`).
- Тонкая полупрозрачная граница между Вело День 1 / Вело День 2 внутри сегмента «Вело» (на 155 км).
- Заливка (цвет — акцент Siberman `#BE0A21`) от 0 до текущей позиции.
- Маленькая точка-маркер на границе заливки.
- Компактный чип над маркером с километражем внутри текущего этапа: `{X} / {Y} км`.
- Название текущего этапа — жирным в подписи под полосой (остальные два — обычным начертанием).

### Состояния

| Состояние | Маркер | Чип/подпись |
|---|---|---|
| Не стартовал (`currentStage(row) === null`) | на 0 км | — (не показываем чип) |
| Активен | на позиции последней достигнутой КТ | `{км внутри этапа} / {длина этапа} км` |
| DNF/DSQ | застывает на последней достигнутой КТ — то же положение, что у активного, дальше не двигается | то же, что у активного (chip не меняет текст на «Сошёл») |
| Финишировал (дошёл до последней КТ бега) | полоса залита целиком (100%) | чип/подпись — `Финиш` вместо километража |

### Данные

Без нового backend. Источник — существующие хелперы `siberman-common.js`:

```js
const stage = currentStage(row);                 // null | 'swim' | 'bike_day1' | 'bike_day2' | 'run'
if (stage) {
    const { seq } = lastReached(row.cp, stage);
    const kmInStage = CHECKPOINT_DIST_KM[stage][seq];
    const stageLenKm = CHECKPOINT_DIST_KM[stage][STAGE_MAX_SEQ[stage]];
    const globalKm = STAGE_KM_OFFSET[stage] + kmInStage;
    const virtualX = kmToVirtualX(globalKm);      // % ширины полосы
}
```

Для эстафетных команд — тот же расчёт, но на объединённом `teamGapRow(team).cp` (как уже делает `buildPositionDatasets`).

Финиш — определяется так же, как везде в проекте: `stage === 'run' && seq === STAGE_MAX_SEQ.run`.

### Изменения в коде

- `static/js/siberman-common.js` — перенести `POSITION_X_SEGMENTS`, `kmToVirtualX()` сюда из `results.html` (сейчас там дублирования нет, но новый компонент бегунка нужен в обоих файлах — выносим по тому же принципу, что и остальные общие хелперы).
- `templates/siberman/participant.html` — новая функция `progressBarHtml(row, isTeam)`, вызывается в `renderIndividual()`/`renderTeam()` сразу после блока ФИО/названия.
- Новые CSS-классы (аналог мокапа): `.pb-track`, `.pb-seg`, `.pb-fill`, `.pb-boundary`, `.pb-marker-dot`, `.pb-inline-chip`, `.pb-stage-labels` — добавить в `<style>` `participant.html` (или общий CSS-файл, если он есть у Siberman-страниц — проверить при реализации).
