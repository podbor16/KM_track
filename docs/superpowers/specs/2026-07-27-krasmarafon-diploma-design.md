# Спека: диплом участника (Красмарафон)

**Дата:** 2026-07-27
**Статус:** Approved (брейншторминг с визуальным компаньоном)
**Страница:** новая, точка входа — `/athlete-profile`

---

## Контекст

Красмарафон хочет выдавать участникам персональный «диплом» — картинку с фоном мероприятия, ФИО, чистым временем, местами (абсолют/пол/категория) и картинкой медали снизу, с кнопками «Скачать» и «Распечатать». Дизайн готовится дизайнером под конкретный забег/дистанцию непосредственно перед стартом (референс — уже готовый диплом «Женская семёрка»).

В проекте на сегодня: нет PDF/canvas-библиотек, нет per-событие полей для брендинг-картинок в конфиге событий (`config/events/*.yaml`), нет стабильного URL на «один результат одного участника» для Красмарафона (только cross-race поиск по ФИО на `/athlete-profile` и общая таблица `/results`). Ближайший архитектурный референс — `templates/siberman/participant.html` (стабильный URL по bib+год) и уже существующий паттерн «печать через `window.print()` на отдельной минимальной HTML-странице» (`static/js/analytics-results.js:exportResultsPdf`).

---

## Часть 1 — Точка входа

Кнопка «🏅 Диплом» — в карточке гонки в истории забегов на `/athlete-profile` (там, где уже отображается `event_name`/`event_distance`/места за конкретный забег, `templates/krasmarafon/athlete-profile.html:~815-870`).

Кнопка показывается, только если ОБА условия верны:
1. Для этой дистанции этого события сконфигурирован дизайн диплома (Часть 3) — если нет, дистанция не участвует в фиче совсем, ничего не ломается для остальных событий.
2. У участника есть реальный результат по этой дистанции (та же дистанция должна быть «отслеживаемой» — `DistanceConfig.tracked`/`db_event_id` заполнен) — символические/нетаймированные дистанции (детский забег 500м, прогулочные 2км без чипов) диплом не получают.

Другие точки входа (кнопка в общей таблице `/results`, отдельная страница поиска) — сознательно не делаем сейчас (см. «Не делаем сейчас»).

## Часть 2 — Роут и данные

Новый роут: **`GET /diploma/{event_id}/{bib}`** — рендерит самостоятельную HTML-страницу (без общей шапки сайта — полноэкранная карточка + две кнопки). Публичный, без авторизации — как `/results`, диплом можно переслать прямой ссылкой. `event_id` — это `db_event_id` конкретной дистанции (в модели Красмарафона у каждой дистанции события уже свой `db_event_id`, отдельный «этап»/«год» не нужен отдельным сегментом URL).

**Данные** — новая функция в `src/analytics/db_results.py`, адаптация уже существующей `get_race_results_by_event_id` (`db_results.py:47-140`, там уже есть весь нужный список колонок) с доп. условием `AND r.start_number = %s LIMIT 1` — однострочный lookup по `(event_id, bib)`, без коллизий номеров между событиями/годами (в отличие от `find_result_by_client_id`, которая не фильтрует по `event_id`).

**Поля из результата** (см. исследование колонок `results`):
- ФИО — `surname`+`name`
- Время — **`time_clear_finish`** (чистое/net, НЕ `time_gun_finish`) — по явному запросу пользователя
- Место в абсолюте — **`rank_absolute_clean`**
- Место по полу — **`rank_sex_clean`**
- Место в категории — **`rank_category_clean`**, подпись — `category` (через уже существующий `stripCategoryBirthYear()`, `athlete-profile.html:234-237`)

Важно: используем именно `_clean`-варианты рангов (net-based), а не обычные (`rank_absolute`/`rank_sex`/`rank_category`, gun-based) — которые сейчас показывает `athlete-profile.html`. Раз время на дипломе чистое, место должно быть посчитано тоже по чистому времени, иначе цифры будут противоречить друг другу на одной картинке. Это осознанное расхождение с тем, что сейчас показывает `athlete-profile.html` (там — gun-based ранги) — красиво, но не в скоупе этой задачи менять существующую страницу профиля.

**Строка «Пол»** рисуется, только если у события/дистанции есть участники обоих полов (иначе, как на Женской семёрке — все `Ж`, строка бессмысленна). Определяется на бэкенде при рендере диплома — простая проверка `DISTINCT sex` среди результатов события/дистанции. Строка «Категория» — рисуется всегда, когда `rank_category_clean` не `NULL`.

## Часть 3 — Конфиг дизайна per-событие/дистанция

Новое опциональное поле `diploma` в `DistanceConfig` (`src/config/event_loader.py`):

```yaml
distances:
  - distance: "7km"
    distance_km: 7
    db_event_id: 123
    diploma:
      background: "static/images/diplomas/women7/7km/background.png"
```

**Скорректировано после получения реального ассета от дизайнера (Женская семёрка, 2026-07-27):** медаль, название события и подпись дистанции нарисованы дизайнером прямо в самой фоновой картинке (единственный файл `background`), а не отдельным изображением поверх шаблона — исходное предположение про отдельный `medal.png` было основано на моковом превью, не на реальной вёрстке дизайнера. Поверх фона размечены два прозрачных прямоугольника-плейсхолдера — под блок «ФИО + время» и под блок «места» — их позиция (в % от размеров картинки) измерена по пикселям конкретного ассета и захардкожена в `templates/krasmarafon/diploma.html`. Если следующий дизайн будет присылаться с другой разметкой плейсхолдеров (другие пропорции/расположение) — проценты в шаблоне нужно будет пересчитать под новую картинку.

Если блок `diploma` отсутствует у дистанции — фича для неё выключена целиком (кнопка не показывается, роут отдаёт 404). Ассеты — новая папка `static/images/diplomas/<event_code>/<distance>/`, отдельно от текущей `static/images/events/` (та используется вручную/не по коду, трогать не будем).

Дизайн диплома — **один шаблон вёрстки для всех событий** (см. Часть 4) — дизайнер готовит один полный фон (с уже вписанными медалью/лого/названием) под фиксированные позиции текстовых плейсхолдеров. Кастомные позиции per-событие — не делаем сейчас (YAGNI, пока нет примера, требующего другой раскладки).

## Часть 4 — Рендер страницы

HTML/CSS оверлей поверх фоновой картинки-фона (растягивается на весь экран/лист), поверх — блоки с относительным позиционированием (проверено на визуальном мокапе, одобрено пользователем):
- Верх: название события (2 строки) + лого КМ
- Строка «Дистанция: N км»
- Карточка: ФИО + чистое время (крупно)
- Карточка: Абсолют / [Пол] / Категория — каждое `<строка label — число>`
- Медаль-картинка снизу по центру

Один Jinja2-шаблон `templates/krasmarafon/diploma.html`, данные (Часть 2) передаются при рендере (server-side), без доп. fetch на клиенте.

---

## Часть 5 — Скачать / Распечатать

- **Скачать** — `html2canvas` (новая клиентская зависимость, vendored в `static/lib/`, как уже сделано с Chart.js) рендерит div диплома в canvas → `canvas.toDataURL('image/png')` → скачивание через `<a download>`.
- **Распечатать** — `window.print()` + `@media print` (новый паттерн для этого приложения — нигде в `templates/krasmarafon` пока нет `@media print`, но это стандартный CSS, ничего экзотического): скрыть обе кнопки при печати, карточка — на всю печатную страницу.

## Не делаем сейчас

- Точки входа с `/results` (общая таблица) и отдельная страница поиска диплома — только `/athlete-profile` (Часть 1).
- Массовая пакетная генерация/архив дипломов всех участников события разом.
- Отправка диплома по email/мессенджерам.
- Кастомное позиционирование текстовых полей per-событие (только один общий шаблон вёрстки).
- Правки существующей `athlete-profile.html` под net-based ранги — расхождение с дипломом (Часть 2) осознанно оставляем как есть, не в скоупе.

## Как включить диплом для события (после того как дизайнер подготовил фон)

**Обновлено 2026-07-31:** после второго реального дизайна (Женская семёрка — 1080×1920, боксы с 24.8%; «Достигая цели» — 705×1280, боксы с 41.7%) стало ясно, что пропорции картинки и позиция плейсхолдеров у каждого дизайнера свои. Позиции боксов и соотношение сторон вынесены из шаблона в конфиг события (`DiplomaConfig`/`DiplomaBoxConfig`, `src/config/event_loader.py`) — `templates/krasmarafon/diploma.html` больше не редактируется под конкретный дизайн, он общий для всех событий.

Чтобы включить фичу для конкретного забега:

1. Положить один полный `background.png`/`.jpg` (лого/название/медаль/декор уже вписаны дизайнером) в `static/images/diplomas/<code события>/<slug дистанции>/`
2. Измерить пиксельные координаты двух плейсхолдеров под текст (например через PIL — цветовой скан плейсхолдера, как это делалось для обоих реальных ассетов) и перевести в проценты от размеров картинки.
3. В `config/events/<code>.yaml`, в нужной дистанции добавить (все поля обязательны — магических дефолтов нет):
   ```yaml
   diploma:
     background: "static/images/diplomas/<code>/<slug>/background.jpg"
     width_px: <реальная ширина картинки в px>
     height_px: <реальная высота картинки в px>
     name_box:  {top: <%>, left: <%>, width: <%>, height: <%>}   # блок ФИО + время
     ranks_box: {top: <%>, left: <%>, width: <%>, height: <%>}   # блок мест
   ```
4. Задеплоить (или подождать TTL-кеша конфигов, 30 сек) — кнопка «Диплом» появится в карточках этой дистанции на `/athlete-profile` автоматически, код трогать не нужно.
