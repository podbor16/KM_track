# Жеребьёвка Siberman 2028 — дизайн

**Дата:** 2026-10-14 · **Эфир:** 27.10.2026, 15:00 МСК (ВКонтакте) · **Статус:** согласован с пользователем по частям 1–6

Контекст, ответы организаторов и разбор эфира 2027 — Obsidian `knowledge/decisions/2026-10-12-siberman-draw-2028-tasks.md`.

## Цель

Провести жеребьёвку регистраций на Siberman 2028 в прямом эфире через нашу систему:
оператор (пользователь) отмечает в админке участника, чей физический шарик вытянули
ведущие (Коля, Миша); через 2–3 секунды он появляется на публичной странице
siberman515.com/draw2028 (Тильда, наши блоки через iframe) и в графике режиссёра (vMix).
После эфира директор гонки ведёт статусы оплаты.

## Как проходит жеребьёвка (из ответов пользователя)

- Одна карточка (шарик) = один шанс. Шарики по цветам: **красный — wild card,
  синий — эстафеты, чёрный — личники**. Мужчины и женщины одного цвета.
- **Раунд 0 — wild card (15 человек, отмечены в таблице).** Зрителям заранее не известны;
  ведущие высыпают 15 красных шариков и называют по одному. Порядок объявления = порядок
  в зачёте и в списке wild card для эфира.
- **Раунд 1 — эстафеты.** Тянут до последнего шарика: первые места до вместимости — победители
  (вместе с wild card), остальные — лист ожидания.
- **Раунд 2 — повторные личники** (отдельная ёмкость, чёрные): до квоты повторных
  (своя для мужчин и для женщин, вместе с wild card-повторниками). Невытянутые → раунд 4.
- **Раунд 3 — новички** (вторая ёмкость, чёрные): до квоты новичков. Невытянутые → раунд 4.
- **Раунд 4 — все оставшиеся личники** (обе ёмкости ссыпают в одну): добирают места мужчин
  и женщин, затем тянут всех — листы ожидания М и Ж, до последнего шарика.
- Вытянули шарик человека, который уже стоит в списке, — шарик пропускают.
- «Повторный» = есть хотя бы один старт в личном зачёте Siberman (колонка таблицы).
- Числа мест (М, Ж, эстафеты) и квоты раундов **ещё не утверждены** → настраиваются в админке.

## Данные (БД `siberman`, миграция `013_draw.sql`)

Все таблицы — по году жеребьёвки (`draw_year`), 2029 не затрёт 2028.

**`draw_applicants`** — заявки из таблицы организаторов:
`id, draw_year, format ENUM('individual','relay'), surname, name, gender ENUM('M','F') NULL
(у эстафеты NULL), city, pool ENUM('wildcard','relay','repeat','novice'), is_wildcard,
chances (итог), starts_individual, starts_relay, draw_accumulated, is_local, duathlon_222,
race_24h, tattoo, relay_swim, relay_bike, relay_run (ФИ строкой), wildcard_reason,
results_text, payment_status ENUM('none','pending','paid','unpaid') DEFAULT 'none',
payment_comment, payment_updated_at`. UNIQUE `(draw_year, surname, name, format)`.

Пул при загрузке: wild card → `wildcard`; эстафета → `relay`; личник со стартами в личном
зачёте > 0 → `repeat`, иначе `novice`. У wild card `pool='wildcard'`, но для подсчёта квот
повторных/новичков учитывается по стартам (wild card-повторник засчитывается в квоту повторных).

**`draw_config`** — `draw_year PK, capacity_men, capacity_women, capacity_relay,
quota_repeat_men, quota_repeat_women, quota_novice_men, quota_novice_women
(все NULL до утверждения), current_round TINYINT (0..4), imported_at,
auto_invite_until DATE (по умолчанию 2027-01-01 — после этой даты автопередача ⏳ выключена)`.

**`draw_picks`** — журнал вытягиваний: `id, draw_year, applicant_id, round, category
ENUM('men','women','relay'), position_key, created_at, cancelled_at NULL, replaced_by NULL`.
`position_key` — ключ порядка в зачёте: у новой записи = её `id`, у исправления = `position_key`
заменённой записи.
UNIQUE на активную запись участника (защита от двойного клика): проверка в транзакции
`SELECT … FOR UPDATE` по `(draw_year, applicant_id, cancelled_at IS NULL)`.

**`draw_audit`** — журнал изменений статусов оплаты и исправлений: `id, draw_year,
applicant_id, action, old_value, new_value, created_at, admin_user`.

## Логика (`src/siberman/draw/` — чистые функции + слой БД)

- **Списки зачётов** строятся из активных `draw_picks` по `position_key`: категория по формату/полу,
  номер = порядок. №1…capacity — «Победитель», дальше — «Лист ожидания».
  Список фиксированной длины для эфира: пустые строки до capacity, затем лист ожидания.
- **Вытянуть:** участник должен быть в пуле текущего раунда (раунд 0 — wildcard;
  1 — relay; 2 — repeat; 3 — novice; 4 — repeat+novice без вытянутых) и не вытянут.
  Иначе — отказ с причиной («уже вытянут: Мужчины №12», «не в этом раунде: эстафета»).
- **Исправить** (replace): исходная запись получает `cancelled_at` + `replaced_by`, новая
  запись (другой участник, та же категория) — `position_key` исходной → номер в зачёте
  сохраняется. Новый участник проходит те же проверки, что и при «Вытянуть».
- **Отменить** любую запись: `cancelled_at`; номера ниже в том же зачёте сдвигаются вверх.
  Обе операции — с подтверждением в UI.
- **Счётчики раунда** для оператора: повторные М/Ж (с wild card), новички М/Ж, места М/Ж/Э,
  сколько людей и шариков осталось в ёмкости раунда.
- **Вероятность попасть в победители** (Monte Carlo, чистый Python, 5000 прогонов):
  от текущего состояния доигрываем раунды по правилам; выбор человека взвешен его шансами,
  после выигрыша остальные его шарики не участвуют (= взвешенная выборка людей без
  возвращения: ключ `random()**(1/chances)`, сортировка). Пересчёт при каждом изменении
  журнала, в фоне; публике отдаётся последний посчитанный результат. Пока места/квоты не
  заданы — колонка скрыта. Тест с фиксированным seed.
  **Без numpy** (решение 2026-10-14): замер на 240 участниках × 5000 прогонов — выборка
  ~380 мс на Python против ~75 мс на numpy; весь пересчёт ~0,5–0,8 с, в фоне раз на
  вытягивание — для зрителей незаметно; numpy = новая зависимость перед эфиром и +13 МБ
  на воркер при недавних проблемах с RAM. Выборка — в одной функции, чтобы при нужде
  заменить на numpy.
- **Wild card не утекает:** до объявления ни один публичный эндпоинт не содержит
  wild card-заявок (ни в аквариуме, ни в счётчиках людей/шариков). Публично wild card —
  обычные победители (без отметки); отметка «WC» — только в админке.
- **Оплаты:** статус меняет директор (вкладка «Оплаты» и сводка). Переходы свободные,
  каждое изменение — в `draw_audit`. Номера в списках не меняются. Публично — значки
  ⏳ pending, ✅ paid, ❌ unpaid, пусто — none.
- **Автопередача ⏳** (предложение пользователя): директор ставит ❌ → система ставит ⏳
  первому в листе ожидания того же зачёта со статусом none и показывает «⏳ поставлен:
  ФИ (зачёт №N) — отправьте счёт». Запись в `draw_audit` с пометкой «авто» и ссылкой на
  ❌, вызвавший её. Директор снимает ❌ → система **предлагает** (не делает молча) снять
  авто-⏳. Лист ожидания пуст → предупреждение. Действует только до `auto_invite_until`
  (правила: передача очереди до 1 января), после — статусы только вручную.

## Загрузка таблицы организаторов

Админка → «Загрузить таблицу»: xlsx (лист «Спец вставка», заголовки по имени колонки) →
отчёт без записи: заявок по пулам и полу, шариков, ошибки (нет пола у личника, нечисловые
шансы, сумма шансов ≠ 1 + доп., дубль ФИ) → «Записать». Повторная загрузка заменяет заявки
года; **запрещена, если в `draw_picks` уже есть записи**. Отметки «!» и «Участвует 2027» —
игнорируются (решение организаторов: обычные участники). Эстафета — по капитану,
названия команды нет.

## Админка (`/siberman/admin`, существующая авторизация)

Новые вкладки: **«Жеребьёвка»** (экран оператора), **«Оплаты»**, **«Настройки жеребьёвки»**
(места/квоты, загрузка таблицы, «Очистить журнал» — подтверждение вводом «2028»).

Экран оператора (макет согласован):
- переключатель раунда в цветах шариков, текущий раунд хранится в `draw_config`;
- строка счётчиков раунда;
- поиск по первым буквам фамилии **только по ёмкости текущего раунда**; уже вытянутые и
  чужие группы — серым с причиной; один результат → Enter добавляет, несколько — ↑↓ + Enter;
  при совпадении ФИ различаем по городу;
- предупреждение «уже вытянут — Мужчины №N»;
- журнал всех действий, у каждой строки «Исправить» и «Отменить» (с подтверждением);
- справа три зачёта, обновляются сразу, «WC» у wild card;
- клик по любой строке → сводка: город, пол, шансы с разбивкой, старты/финиши Siberman по
  годам (из нашей БД: `person_key`, личный + эстафета), состав эстафеты, место в жеребьёвке
  (зачёт, №, раунд, время, wild card), статус оплаты и комментарий (редактируются),
  тексты заявки. Подпись: «накопленные шансы за жеребьёвки (обнуляются после выигрыша)».
- **Читаемость:** у всех элементов явно заданы фон и цвет текста; контраст проверяется в
  браузере (agent-browser `eval` getComputedStyle) до сдачи.

## Публичные блоки (iframe в Тильде)

Страницы на `live.siberman515.com`, стиль Siberman (Onest, #003D62, #BE0A21), опрос API
раз в 2–3 с, ответы из кэша:
- **`/draw/2028/aquarium`** — группы (личники / эстафеты; до раунда 4 — повторные и новички
  отдельно) с числом людей и шариков, текущий раунд, поиск «найти себя», таблица:
  ФИ, город, шансы, вероятность. **Вытянутые убираются сразу.** Wild card не показываются.
- **`/draw/2028/results`** — вкладки Мужчины / Женщины / Эстафеты; разделы «Победители ·
  N мест» и «Лист ожидания»; статусы оплаты; последний вытянутый подсвечен.
- Для Тильды — готовый HTML-фрагмент (блок T123): iframe + скрипт автовысоты
  (`postMessage` высоты из нашей страницы). Ответ API: `Cache-Control: no-store`.

## Ссылки для vMix (опрос раз в 3 с, без авторизации)

`/api/siberman/draw/2028/feed/{men|women|relay|wildcard|last}.{json|csv}`
- `men/women/relay`: строки `№, ФИ, город, раздел (Победитель/Лист ожидания), статус`;
  фиксированная длина (пустые строки до мест), затем лист ожидания. Страницы по 20 строк
  режиссёр переключает сам.
- `wildcard`: объявленные wild card в порядке объявления (в эфире выделяются).
- `last`: последний вытянутый (ФИ, город, зачёт, №, раунд).
JSON — массив объектов с одинаковыми ключами (для Data Source vMix), CSV — UTF-8 с BOM.
Формат выбирает режиссёр на репетиции.

## Кэш и надёжность

- Состояние только в БД (3 воркера gunicorn). Публичные ответы — кэш в памяти воркера на 1 с,
  ключ — версия журнала (`MAX(id)` + число отмен + `MAX(payment_updated_at)`).
- Вероятности — кэш по той же версии, пересчёт в фоне.
- Двойной клик/повтор запроса — защищено проверкой в транзакции.
- Утром 27.10 — бэкап БД `siberman`.
- Репетиция идёт на `draw_year=2028`, после — «Очистить журнал» (vMix настраивается на
  настоящие ссылки один раз).

## Тестирование

- Unit: построение зачётов и разделов, пулы раундов, счётчики квот, отказ «уже вытянут» /
  «не в этом раунде», исправление (номер сохраняется) и отмена (сдвиг), wild card не
  попадает в публичные ответы до объявления, симуляция (seed; вырожденные случаи:
  мест ≥ людей → 100%, один человек), импорт (отчёт, ошибки, запрет после начала), CSV/JSON фидов.
- Браузер (agent-browser): админка (поиск, Enter, исправить/отменить, контраст),
  обе публичные страницы внутри тестовой iframe-страницы, мобильная ширина.
- Нагрузка: публичные эндпоинты из кэша — без запросов к БД при попадании в кэш.
