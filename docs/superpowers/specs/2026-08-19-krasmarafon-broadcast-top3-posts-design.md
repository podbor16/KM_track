# Генератор постов Топ-3 для трансляции Жары — дизайн

## Контекст и цель

Оператору `/admin` нужен готовый к копированию текстовый пост «Топ-3 мужчины» / «Топ-3
женщины» на каждой контрольной точке дистанций «5 км» и «21.1 км» Жары — вставлять в
соцсети/мессенджер по ходу гонки, по аналогии с генератором постов трансляции Siberman
(`templates/siberman/admin.html`, вкладка «Трансляция»).

Никакого нового backend-кода не требуется — вся нужная информация уже вычисляется
`generate_top10_json()` (`src/krasmarafon/services/live_top10_export.py`) и пишется в
статичные JSON-файлы `load_race_results.py --continuous --broadcast-json` во время
гонки (см. [[2026-08-18-zhara-live-top10-broadcast-json-design]]). Задача — новая
вкладка «Трансляция» в `templates/krasmarafon/admin.html`, чисто клиентский JS: fetch
уже существующего JSON → рендер текста.

## Объём

- Только Жара, только «5 км» и «21.1 км» (у «2 км» нет промежуточных КТ вообще —
  `events.checkpoint_distances IS NULL`, топ-N по отметкам для неё не имеет смысла —
  то же ограничение, что и у самого live-top10 JSON).
- На каждой отметке — **два ОТДЕЛЬНЫХ поста**: «Мужчины» и «Женщины» (не объединённый).
- Топ-3, не топ-10 (JSON уже содержит топ-10 — берём первые 3 записи каждого списка).
- Источник — уже существующие JSON-файлы, по фиксированной конвенции путей:
  - «5 км» → `/live/zhara_5km_top10.json`
  - «21.1 км» → `/live/zhara_21km_top10.json`

  (эти два имени файлов — контракт с `config/loader/zhara_5km.env`/
  `zhara_21km.env`/`LOADER_BROADCAST_JSON`, которые ещё предстоит создать перед днём
  гонки — см. пункт бэклога «Live-топ-10 на каждой отметке для трансляции Жары»,
  «Ждёт до дня гонки»).

## UI (новая вкладка «Трансляция» в `/admin`)

По образцу существующих вкладок (`ADMIN_TAB_STORAGE_KEY`/`switchTab` — общий механизм,
ничего нового изобретать не нужно):

1. Селектор дистанции («5 км» / «21.1 км») → fetch соответствующего JSON, заполняет
   список отметок значениями `checkpoints[].label` (уже готовые строки вида
   «КТ1 (5.0 км)» … «Финиш» — используем как есть, парсить не нужно)
2. Селектор отметки (`checkpoints[].code` как value)
3. Две кнопки — «Сгенерировать (Мужчины)» и «Сгенерировать (Женщины)» — каждая
   независимо заполняет свой `<textarea readonly>` + рядом кнопка «Копировать»
   (`navigator.clipboard.writeText`, как у Siberman)

Если fetch JSON падает (404/сетевая ошибка — гонка ещё не началась, файл не создан) —
текстовое сообщение в области вывода: `«Нет данных — трансляция ещё не активна»`,
никакой необработанной JS-ошибки в консоли.

## Формат поста

Источник данных на одну запись — `checkpoint.top10_male`/`checkpoint.top10_female` из
JSON (уже отсортированы по возрастанию времени = по месту), берём `.slice(0, 3)`.
Форматирование markdown-совместимо с Siberman (`**bold**`/`__italic__` — Telegram
Markdown, рендерится жирным/курсивом там, где парсер это поддерживает; если платформа
markdown не понимает, звёздочки/подчёркивания остаются видимыми как есть — то же
поведение, что уже принято для Siberman, ничего нового не решаем):

```
**{Мужчины|Женщины}. {Отсечка {N} км|Финиш}**

1. {surname} {name}
⏱️{time}{ (+ЧЧ:ММ:СС|+ММ:СС), если не лидер}
{pace} мин/км

2. {surname} {name}
⏱️{time} (+...)
{pace} мин/км

3. ...

__👉 ссылка на лайв-результаты: https://analytics.krasmarafon.ru/results__
```

Правила:
- **Заголовок** (жирный, первая строка): `«{Мужчины|Женщины}. Отсечка {N} км»`, где
  `{N}` — дистанция КТ от старта в км. JSON не отдаёт это число отдельным полем — оно
  уже встроено в `checkpoint.label` (формат из `live_top10_export.py`:
  `"КТ{i} ({checkpoint_distances[i]} км)"` для промежуточных точек, просто `"Финиш"`
  для финиша). Извлекаем `{N}` regex'ом `/\(([\d.]+)\s*км\)/` по `checkpoint.label` —
  не пересчитываем заново на клиенте. Если `checkpoint.code === 'finish'` (регекс не
  матчится, `label === 'Финиш'`) — заголовок `«{Мужчины|Женщины}. Финиш»` без «Отсечка».
- **Время** (`⏱️` + `entry.time`): значение уже в формате `ЧЧ:ММ:СС` из JSON — если
  часовая часть `"00"`, отбрасываем её (`"00:15:00"` → `"15:00"`), иначе оставляем как
  есть (`"01:15:00"` — часовая гонка на 21.1 км вполне может выйти за час).
- **Отставание**: `entry.gap_sex` из JSON уже готов в формате `"Лидер"`/`"+ММ:СС"`/
  `"+ЧЧ:ММ:СС"`. Для лидера (значение `"Лидер"`) — ничего не дописываем к времени. Для
  остальных — `" (" + gap_sex + ")"` сразу после времени, на той же строке
  (`⏱️20:00 (+05:00)`).
- **Темп**: `entry.pace` из JSON уже в формате `"M:SS"` — просто `{pace} мин/км`.
  Если `entry.pace === null` (не должно происходить на практике для строки, у которой
  есть `time`, но JSON формально это допускает) — не показывать вторую строку вовсе,
  оставить только время.
- **Пустой топ-3**: элементы, до которых ещё никто не дошёл, не включаются — если в
  `top10_male`/`top10_female` меньше 3 записей, показываем сколько есть (1 или 2), без
  плейсхолдеров вида `«3.»`. Если список пуст полностью — вместо всего поста короткий
  текст `«Нет данных для этой отметки — пока никто не финишировал.»` (тот же принцип,
  что у Siberman: `«Нет данных для выбранной КТ (никто из категории ещё её не
  прошёл).»`).
- **Ссылка** (курсив, последняя строка): статична, не зависит от дистанции/отметки —
  `__👉 ссылка на лайв-результаты: https://analytics.krasmarafon.ru/results__`.

## Обработка ошибок

- JSON недоступен (404 — файл ещё не создан загрузчиком) или сетевая ошибка → дружелюбное
  сообщение в области вывода, не исключение.
- JSON доступен, но выбранной отметки в нём нет (не должно происходить при штатной
  работе UI, т.к. список отметок строится из того же JSON) — тот же текст, что при
  полностью пустом топ-3.

## Тестирование

- JS-юнит-тесты на чистую функцию форматирования поста (`node:vm`, тот же приём, что
  уже используется для Siberman/Krasmarafon JS без выделенного фреймворка) — время с
  часами/без часов, лидер без gap/не-лидер с gap, пустой список (0/1/2 записи), КТ vs
  Финиш в заголовке, «Мужчины» vs «Женщины» в заголовке.
- Живая проверка в браузере на синтетическом JSON (реальные данные появятся только в
  день гонки, когда `--continuous --broadcast-json` реально запущен) — подложить тестовый
  JSON-файл по одному из двух путей, открыть `/admin` → «Трансляция», убедиться, что
  выбор дистанции/отметки работает, тексты обоих постов совпадают с примером из этого
  документа, копирование в буфер работает.

## Явно вне объёма

- Реальная автоматическая публикация (Telegram Bot API и т.п.) — пользователь явно
  выбрал вариант «генератор текста + ручное копирование», как у Siberman.
- Абсолютный топ-3 (без разделения по полу) — не запрошен, только мужчины/женщины
  раздельно.
- «2 км» — без промежуточных КТ, вне объёма (см. «Объём» выше).
- Другие события Красмарафона (не Жара) — фича завязана на конкретные два JSON-файла
  Жары, не обобщается на произвольное событие.
