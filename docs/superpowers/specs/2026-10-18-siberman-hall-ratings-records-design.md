# Siberman: рейтинг, рекорды, статистика, география и страница спортсмена — дизайн

Дата: 2026-10-18. Статус: согласовано в брейншторме, ждёт ревью спецификации.
Заметка с ходом обсуждения: Obsidian `knowledge/decisions/2026-10-18-siberman-ratings-records-page.md`.
Макеты: `.superpowers/brainstorm/36-1792309228/content/` (rating-v4, records-v8, athlete-v2, stats-geo-v10).

## 1. Цель

Страница siberman515.com/results (Тильда) сейчас ведётся вручную: таблицы рейтинга, статистика, рекорды, география. Заменяем их блоками, которые строятся из нашей БД Siberman (архив 2016–2026 + новые годы) и не требуют ручного обновления. Добавляем страницу спортсмена за все годы.

**В объёме:** реестр людей (кто есть кто, с тёзками), рейтинг, таблица рекордов с историей, статистика, география, страница спортсмена, медали за финиши, вкладка «Люди» в админке, загрузка дат рождения из заявок Тильды.
**Вне объёма:** «Главные события год за годом» (остаётся текстом в Тильде); правки самой Тильды (делает пользователь по нашему сниппету); изменение правил рекордов организаторов (см. §10).

## 2. Устройство

- Четыре блока для Тильды (iframe, автовысота через `postMessage`, как у жеребьёвки) на live.siberman515.com:

## 3. Реестр людей

### 3.1 Почему не «фамилия + имя»
Бывают тёзки, в том числе из одного города. Проверка архива 2016–2025 (только числа):
- личный стартовый номер закреплён за человеком навсегда (подтвердил пользователь): 24 из 24 повторных личников — тот же номер, ни один личный номер не носили разные ФИ;
- у эстафет номер — номер команды на год (73 из 73 групп «год+номер» — несколько людей), у эстафетчиков он меняется; при переходе эстафета ↔ личный зачёт номер другой;
- «одно ФИ дважды в году» — 6 случаев, все один номер (эстафетчик на нескольких этапах) → сравнивать по (год, номер);
- дата рождения есть в заявках Тильды с 15.10.2024 (форма 807405240; у эстафеты — у каждого участника): 561 человек; в архиве ДР найдётся у 79 из 337 (у тех, кто бежал в 2024–2025, — у 49 из 126). В заявках 7 ФИ с разными ДР (3 похожи на опечатку) → ДР не единственный ключ;
- e-mail ключом не годится (13 человек меняли, 23 адреса общие у разных ФИ).

### 3.2 Модель данных (миграция `014_persons.sql`)
- `siberman_persons`: `id`, `surname`, `name`, `gender` (`M`/`F`), `birthdate` DATE NULL, `bib_individual` VARCHAR(10) NULL UNIQUE, `city`, `country` (последнего старта), `created_at`, `updated_at`.
- `siberman_person_links (race_year, bib, relay_stage) → person_id, manual, name_key` — привязка выступления к человеку по естественному ключу. Не колонка в `participants`: загрузка Excel удаляет и заново вставляет строки года, привязки (и ручные решения, и id в адресах `/athlete/{id}`) терялись бы. `manual=1` — решение админа; `name_key` — ФИ строки на момент привязки (смена ФИ на том же месте ловится, см. §3.3).
- `siberman_applicants`: `tranid` (из Тильды; у этапников эстафеты — `tranid:swim|bike|run`), `surname`, `name`, `gender` NULL, `birthdate`, `city`, `submitted_at`, `claimed_starts` (сколько стартов на Siberman указал сам; NULL у этапников). Телефоны, e-mail, тексты заявок не храним.
- `siberman_person_reviews` — «проверить»: `kind`, `dedupe_key` (UNIQUE), выступление (`race_year`, `bib`, `relay_stage`) или человек (`person_id`, FK `ON DELETE SET NULL`), `other_person_ids` (кандидаты), `detail`, `status` (`open`/`resolved`/`deferred`).
- `siberman_person_audit` — журнал ручных действий со снимком «до» для отмены.

ДР видна только в админке; ни одно публичное API её не отдаёт.

### 3.3 Привязка выступления к человеку
Строки без фамилии не привязываются. Для остальных:
1. **Сохранённая привязка** действует, если она ручная или ФИ строки то же, что при привязке. Ручная с другим ФИ остаётся, но даёт «проверить» (`manual_name_changed`); автопривязка с другим ФИ (замена этапника, исправленный протокол) разрешается заново и, если ушла к другому человеку, — `relinked`. Автопривязка строки, у которой стёрли фамилию, снимается.
2. **Личник** — по `bib_individual`: номер уже за человеком → этот человек, даже при другом ФИ (`bib_name_change` для подтверждения) или другом поле (`bib_gender_mismatch`). Номера нет → шаг 3, человеку записывается `bib_individual`.
3. **По ФИ** (без псевдонимов) среди людей того же пола; отсеиваются: у кандидата свой другой личный номер (тёзка — без записи), кандидат уже выступает в этом году под другим номером. Один кандидат → он (переход эстафета ↔ личный зачёт — `format_switch`); несколько → новый человек + `namesake_candidate`; кандидаты отсеяны только полом → новый человек + `gender_mismatch`.
4. **ДР из заявок** (по дате подачи, ФИ в любом порядке): ставится автоматически, только если ФИ подходит одному человеку, у него нет другой ДР, город не противоречит и заявитель сам указал старты на Siberman. Иначе — `bd_conflict`, `applicant_ambiguous`, `applicant_city_mismatch`, `applicant_unconfirmed`.

Синхронизация — хвостом `recompute_totals_ranks_records()` после любой загрузки, когда изменился отпечаток протокола (`COUNT` + `BIT_XOR(CRC32(...))` по участникам). Загрузка Excel держит лок реестра на время удаления и вставки строк года; автосинхронизация лок не ждёт. Идемпотентна. Люди без выступлений удаляются, если на них не ссылаются нерешённые «проверить».

### 3.4 Вкладка «Люди» в админке Siberman (`/admin/people`)
- «Проверить» с кнопками под каждый вид: `namesake_candidate`, `gender_mismatch`, `relinked` (слить с кандидатом / другой человек), `bib_name_change`, `bib_gender_mismatch`, `format_switch` (тот же / отделить), `manual_name_changed` (оставить привязку с новым ФИ / отделить), `bd_conflict`, `applicant_ambiguous`, `applicant_city_mismatch`, `applicant_unconfirmed` (записать ДР / не он); «отложить», «вернуть».
- Поиск (ФИ, личный номер, id), карточка: выступления с отметкой «вручную», перенос отмеченных в нового или существующего человека, слияние, правка ДР.
- Журнал: каждое ручное решение отменяется, в том числе не последнее — если позже эти люди, выступления или записи «проверить» не менялись. Снимок «до» включает людей, привязки и затронутые записи «проверить».
- «Заявки и пересборка»: загрузка CSV-выгрузки Тильды (UTF-8 с BOM или cp1251), пересборка привязок с отчётом числами.

### 3.5 Счётчик финишей
«N-й финиш» в трекере — по человеку из реестра (`finish_count_for`); выступление ещё не привязано или нет миграции 014 — по ФИ, как раньше. На архиве 2016–2025 числа совпадают со старым подсчётом. `PERSON_ALIASES` удаляется после выкладки и проверки на проде.

## 4. Рейтинг (`/hall/rating`)
- Вкладки: **Абсолют** (все личники М+Ж, столбец «Пол»), **Мужчины**, **Женщины**, **Эстафеты**.
- Личники: место, № (стартовый номер), участник (ФИ → `/athlete/{id}`), пол (только в «Абсолюте»), город, время (→ карточка года `/participant/{bib}?year=`), год, «Финиш №» с кружком цвета медали. Рекорд — красная пометка.
- Переключатель «Все финиши / Лучший на человека» (у личников), фильтр по году, поиск по фамилии/номеру.
- Время — официальный итог года (`overall_results.total_s`). Место — по времени внутри выборки. DNF/DSQ — в конце без места, с этапом схода. DNS не показываем.
- Эстафеты: один список без деления по полу; место, № команды, название (→ результат команды в год), состав полными ФИ по этапам (каждое → страница человека), время (→ карточка года), год. Итог эстафеты = сумма этапов (плавание + вело д1 + вело д2 + бег), у эстафетчиков нет `overall_results`.

## 5. Рекорды (`/hall/records`)
### 5.1 Таблица
Строки: гонка, плавание, вело всего (д1+д2), вело д1, вело д2, бег. Столбцы: личный зачёт М/Ж, эстафета М/Ж, абсолютно лучшее М/Ж.
- Эстафета в этапах — по полу участника этапа. Строка «гонка»: эстафета — одна клетка без пола (объединённая М+Ж).
- Абсолютно лучшее (вариант А): в этапах — лучшее из личников и эстафетчиков своего пола; в строке «гонка»: М = лучшее из мужчин-личников и эстафет, Ж = лучшее у женщин-личниц.
- В клетке: время, ФИ (→ страница), у эстафеты — команда, год. В абсолютной клетке этапа у эстафетчика — «эстафета», с новой строки название команды (→ результат команды в год рекорда).
- Пометка «НОВЫЙ», если рекорд установлен в последнем году с результатами.
- В рекорды идут только финишировавшие этап (DNF/DSQ — нет; для этапа достаточно его итогового времени, для «гонки» — финиш).

### 5.2 История
Проход по годам по возрастанию: в каждом году для каждой клетки — лучшее время года; если лучше текущего рекорда → новая запись истории (время, человек/команда, год, улучшение). Текущий рекорд = последняя запись. Во всплывающем окне — история клетки (ФИ и команды — ссылки). Окно ставится рядом с клеткой (в iframe нельзя по центру всей высоты), закрывается крестиком / кликом мимо / Esc. Клик по ФИ/команде → переход, по остальной клетке → история.

### 5.3 Сверка
Тест на архиве: текущие рекорды совпадают с таблицей организаторов (лист «Рекорды» в `Online results Siberman.xlsx`; значения времён фиксируются в тесте). Расхождения — показать пользователю до выкладки. Живые рекорды `siberman_records` (трекер) не трогаем; сверяем, что текущие рекорды hall для последнего года совпадают с ними.

### 5.4 Цвета и телефон
Столбцы М — голубой (#eef4f9), Ж — розовый (#fbeef0), эстафета «гонки» — белая. Телефон: блок на дисциплину, карточки 2×3 по центру, полные ФИ, названия зачётов жирным, цвет по полу.

## 6. Статистика (`/hall/stats`)
- «Siberman в цифрах · {первый}–{последний год}», личный зачёт — две колонки:
  - **Люди**: N человек стартовали, из них финишировали; мужчин / женщин;
  - **Старты**: N стартов за все годы, из них с финишем; мужских / женских с финишами.
- Строка эстафет: команд, финишировали, людей в составах.
- Итог: всего людей в Siberman (лично + эстафеты, по реестру), стран, городов.
- Таблица по годам: личный старт/финиш, М/Ж, эстафеты старт/финиш, новички (первый старт человека в Siberman), лучшее время года. На телефоне — горизонтальная прокрутка.
- «Старт» = участник со статусом не `dns`. Сверка с текущими цифрами сайта (204/196, 170/165, М 189/184, Ж 15/12, 156/14, эстафет 73/71) — тест на архиве 2016–2025; расхождения показать пользователю.

## 7. География (`/hall/geo`)
- Считаем людей (реестр), город/страна — последнего старта. Переключатель «Все / Личный зачёт / Эстафеты».
- `data/siberman/cities.json`: каноническое название, страна, широта, долгота, список написаний («г. Красноярск», «Krasnoyarsk»…). Заполняется один раз скриптом через Nominatim (с паузой 1 с, User-Agent) и проверяется глазами; новые города при выкладке добавляются тем же скриптом. Не найденный город — в списке без точки на карте, в админке видно «города без координат».
- Карта: Leaflet 1.9.4 + Esri World Light Gray; подпись «Leaflet» с флагом убрана, «Esri» оставлено (условия Esri).
- Страны, откуда есть участники, закрашены (тёмно-синий, прозрачность 0,18), при наведении — «страна · N чел.». Границы — `world-atlas` 2.0.2 `countries-110m` (TopoJSON, `topojson-client` 3.1.0), страна сопоставляется по ISO-коду (в `cities.json` у города — ISO 3166-1 numeric страны). Кольца через линию перемены дат (Чукотка, Алеуты) разворачиваются (+360° к отрицательным долготам), иначе по карте тянутся полосы. Файл границ кладём в `static/vendor/`, а не грузим с CDN на проде.
- Кружок = число людей внутри; при наведении — город, у иностранных — «город, страна»; по нажатию — список людей (ссылки). Близкие города объединяются (`leaflet.markercluster` 1.5.3) с суммой и списком городов при наведении, распадаются при приближении/нажатии.
- Колесо мыши над картой — масштаб, вне карты — прокрутка страницы. Телефон: одним пальцем — прокрутка страницы (подсказка «Двигайте карту двумя пальцами»), двумя — карта (`dragging` выключен на тач, `touch-action: pan-y`); на узком экране старт с видом на Евразию.
- Под картой — списки стран и городов с числом людей.

## 8. Страница спортсмена (`/athlete/{person_id}`)
- Шапка: ФИ, город и страна, «Siberman с {год}», личный номер крупно (если был в личном зачёте).
- Сводка: стартов, финишей лично, эстафет, действующих рекордов.
- Медали по порядку финишей + эстафетная отдельно (меньше); следующая — бледная (возможно уберём, §10).
- Лучшие результаты: гонка и каждый этап (год, «РЕКОРД»), лучшее место, позиция в рейтинге «лучший на человека».
- Все участия по годам: формат (личный — «N-й финиш»; эстафета — этап и команда), итог/DNF с этапом, место абс / среди пола (эстафета — место среди эстафет), времена этапов, ссылка на карточку года.
- Рекорды: действующие и прошлые (кем и когда побит).
- Несуществующий id → 404-страница Siberman.

## 9. Медали (`medals.py`)
Одна функция `medal_for(finish_no, relay=False)`:
1-й личный — античное серебро 100 мм (синяя лента); эстафета — серебро 70 мм; 2-й — матовая чёрная; 3-й — золотая; 4-й — античная медь; 5-й — «хамелеон»; 6-й — чёрный шестигранник; 7-й и дальше — серебряный шестигранник с красной плашкой.
Картинки — `static/img/siberman/medals/*.webp`, вырезаны из фото заказа без гравировки имён (шестигранник 7-го — с фото пользователя). Нет картинки → цветной кружок-заглушка.

## 11. Ошибки и пустые состояния
- БД недоступна → блок показывает «Данные временно недоступны», iframe высоту не теряет; API — 503.
- Год без результатов не попадает ни в рейтинг, ни в статистику.
- Во время гонки текущий год участвует как есть: рекорды этапов обновляются по мере финиша этапов (как живые рекорды трекера), в рейтинг попадают только с итоговым временем.

## 12. Тесты
- Unit: привязка людей (личник по номеру, тёзки с разными номерами, эстафетчик на двух этапах, переход эстафета → личный, разные ДР → «проверить», ручная блокировка не перезаписывается, идемпотентность); разбор CSV заявок (обе формы, эстафетные ДР, плохие даты); медали; рекорды (вариант А, эстафета «гонки» без пола, история); статистика; нормализация городов.
- Integration (локальная БД, тестовый год `2090 + pid % 10`): заполнение реестра на архиве; сверка рекордов с организаторами и статистики с сайтом; публичные API не содержат `birthdate`; счётчик финишей совпадает со старым.
- Браузер (Playwright, `channel="chrome"`): блоки в iframe на десктопе и в эмуляции телефона, автовысота, всплывающая история, жесты карты.
