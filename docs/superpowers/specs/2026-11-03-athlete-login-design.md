# Вход спортсмена по коду из почты (этап А) — дизайн

Дата: 2026-11-03. Статус: согласован с пользователем (brainstorming), ждёт ревью спецификации.
Этап А задачи «согласие на ПД + вход спортсмена» (части 2–3: отправка писем, вход).
Этап Б (части 4–5: заявление карточек, история) — отдельная спецификация после выкладки А.
Obsidian: `inbox/2026-11-03-krasmarafon-athlete-auth`.

## Цель

Человек входит на results.krasmarafon.ru по коду из почты и видит на `/me` заявки, оформленные
с этой почты. Это основа этапа Б (аккаунт = почта; карточки спортсменов заявляются позже).

## Решения (пользователь, 2026-11-03)

- Отправка писем — через **почтовый ящик домена в Яндексе по SMTP** (`noreply@krasmarafon.ru`,
  отдельный ящик, чтобы блокировка отправки не задела рабочую почту). Unisender не используем:
  `sendEmail` добавляет получателя в список контактов, не шлёт глобально отписавшимся, вставляет
  ссылку отписки. Писем после забега не будет — только коды входа.
- Вход разрешён **с любой почтой**, даже если её нет в заявках (человек, которого записывал кто-то
  другой, должен войти и на этапе Б найти себя по ФИ).
- Аккаунт = почта. Ни регистрации, ни паролей.

## Отправка писем

Модуль `src/core/mailer.py`: `send_mail(to, subject, text)`; поставщик по настройке `MAIL_BACKEND`:

- `log` (по умолчанию, разработка и тесты) — письмо пишется в лог;
- `smtp` — `smtplib.SMTP_SSL` (stdlib), `SMTP_HOST=smtp.yandex.ru`, `SMTP_PORT=465`,
  `SMTP_USER`, `SMTP_PASSWORD` (пароль приложения), `MAIL_FROM`. Секреты — только в `.env` на сервере.

Отправка блокирующая → вызывается через `run_in_threadpool`. Ошибка отправки → лог + человеку
«Не удалось отправить код, попробуйте позже».

Лимит Яндекса: по официальной справке 300 писем/сутки через SMTP (для Яндекс 360 для бизнеса может
быть больше — не подтверждено). Длинная сессия снижает поток: код нужен раз на устройство.
Смена поставщика — новая ветка в `mailer.py` + настройка, вызывающий код не меняется.

## Вход

1. «Войти» в шапке сайта → `/me/login`: поле почты, галочка «Чужой компьютер».
2. `POST /me/login` → почта нормализуется (`strip().lower()`), проверяются лимиты, создаётся код:
   6 цифр + токен ссылки; в БД — только хэши (HMAC-SHA256 с `SECRET_KEY`). Письмо: код и ссылка
   `/me/link?t=…`. Ответ всегда один: «Мы отправили код на …» (не раскрывает, есть ли заявки).
3. Ввод кода → `POST /me/verify`. Код и ссылка: живут **15 минут**, одноразовые, **5 попыток** ввода
   на код; новый код делает прежние недействительными.
4. Ссылка `GET /me/link?t=…` показывает страницу с кнопкой «Войти» (`POST /me/link`) — не входит
   сразу: почтовые антивирусы открывают ссылки и «съели» бы одноразовый токен.
5. Успех → сессия, cookie `km_athlete` (не путать с админским `km_session`):
   `HttpOnly`, `Secure` (если запрос пришёл по HTTPS — `X-Forwarded-Proto: https` от nginx; не по
   `settings.DEBUG`: на проде он True), `SameSite=Lax`, `Max-Age` 180 дней; с «Чужой компьютер» —
   без `Max-Age` (до закрытия браузера), в БД срок 1 сутки. В cookie — случайный токен
   (`secrets.token_urlsafe(32)`), в БД — его SHA-256.
6. `/me`: «Выйти» (удаляет эту сессию), «Выйти на всех устройствах» (все сессии почты).

Лимиты (против рассылки кодов на чужие адреса и сжигания лимита Яндекса), считаются по таблице кодов:

- на почту: не чаще 1 кода в минуту и не больше 5 в час;
- с IP (`X-Real-IP` от nginx, иначе `request.client.host`): не больше 10 кодов в час.

Превышение → «Слишком много попыток, попробуйте позже» (код не создаётся, письмо не уходит).

## Данные

Миграция `migrations/athlete_login.sql` (идемпотентно, `CREATE TABLE IF NOT EXISTS`):

```sql
CREATE TABLE IF NOT EXISTS athlete_login_codes (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  email VARCHAR(255) NOT NULL,
  code_hash CHAR(64) NOT NULL,
  link_hash CHAR(64) NOT NULL,
  ip VARCHAR(45) NOT NULL,
  attempts TINYINT NOT NULL DEFAULT 0,
  expires_at DATETIME NOT NULL,
  used_at DATETIME NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_alc_email (email, created_at),
  KEY idx_alc_ip (ip, created_at),
  UNIQUE KEY uq_alc_link (link_hash)
);

CREATE TABLE IF NOT EXISTS athlete_sessions (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  email VARCHAR(255) NOT NULL,
  token_hash CHAR(64) NOT NULL,
  expires_at DATETIME NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  last_seen_at DATETIME NULL,
  user_agent VARCHAR(255) NULL,
  UNIQUE KEY uq_as_token (token_hash),
  KEY idx_as_email (email)
);
```

Время — серверное `NOW()` MySQL (один источник, без расхождения часовых поясов Python/БД).
Чистка: просроченные коды и сессии старше срока удаляются при создании нового кода/сессии
(`DELETE … WHERE expires_at < NOW() - INTERVAL 1 DAY`) — без отдельного планировщика.

## Страница `/me`

Без сессии → редирект на `/me/login`. Раздел «Заявки, которые вы оформили» — заявки, где
`leads.email = почта` или `leads.ma_email = почта` (без учёта регистра), двумя блоками:

- **Предстоящие** (`events.event_date >= CURDATE()` или даты нет): событие, дистанция, дата, участник
  (ФИ), стартовый номер (если присвоен), статус «оплачено» / «возврат».
- **Прошедшие**: то же + время из протокола (результат по `event_id + start_number`), ссылка на
  результаты и диплом (если у дистанции включён диплом); без результата — «нет результата».

Нет: ДР, телефона, города, клуба, истории по карточке (этап Б). Флаг «Без ПД» на `/me` не действует —
это заявки, оформленные самим владельцем почты. Пусто → «Заявок с этой почты не найдено».

## Код

- `src/core/mailer.py` — отправка.
- `src/krasmarafon/services/athlete_auth.py` — коды, лимиты, сессии (SQL через пул
  `db_connection_optimized`), зависимость FastAPI `current_athlete(request) -> str | None`.
- `src/krasmarafon/routers/athlete.py` — `/me`, `/me/login`, `/me/verify`, `/me/link`, `/me/logout`,
  `/me/logout-all`; подключается в `app.py`. Пути под `location /` nginx results.krasmarafon.ru —
  правка nginx не нужна.
- Шаблоны `templates/krasmarafon/me.html`, `me-login.html`; ссылка «Войти»/«Мои заявки» в `header.html`.
- Настройки в `src/config/settings.py` и `.env.example`: `MAIL_BACKEND`, `SMTP_HOST`, `SMTP_PORT`,
  `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM`.

Защита форм от CSRF: все POST — формы того же сайта; cookie `SameSite=Lax` не уходит в
межсайтовых POST, вход/выход не принимают JSON с чужих доменов.

## Ошибки и граничные случаи

- Неверный/просроченный/использованный код или ссылка → «Код неверный или устарел» (без уточнения).
- 5 неверных попыток → код аннулирован, нужно запросить новый.
- Сессия просрочена или удалена «Выйти на всех» → `/me` ведёт на вход.
- Почта с пробелами/заглавными → нормализуется до `strip().lower()` везде (заявки сравниваются через
  `LOWER()`).

## Тесты

- Unit: `mailer` (log/smtp с подменой `smtplib`), хэши и сверка кода, лимиты, срок жизни, одноразовость,
  5 попыток, «новый код гасит старый».
- Интеграция (локальная БД): сквозной вход (код из лога → сессия → `/me` показывает заявки по `email`
  и по `ma_email`), ссылка через страницу с кнопкой, «выйти на всех», лимиты, `/me` без сессии → редирект.
- Ручная проверка пользователем на локальном сервере (обязательна до выкладки).

## До выкладки (от пользователя)

  (`MAIL_BACKEND=smtp`, `SMTP_*`, `MAIL_FROM`).
- Миграция `athlete_login.sql` на проде — с «да» пользователя.
